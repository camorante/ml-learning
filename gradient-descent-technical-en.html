§7 · Non-convexity

Local minima, saddle points and curved valleys

A stationary point () is classified by the Hessian : a minimum if , a maximum if , a saddle point if it has eigenvalues of both signs. In high dimensions, saddle points are far more common than bad local minima. GD can spend a long time near one (the gradient is tiny), but the direction of negative curvature is unstable and any perturbation (SGD noise, momentum) eventually pushes it out. §8 · Practice

Correct gradients and sensible steps

  • Automatic differentiation. Reverse mode (backpropagation) computes at a cost of a few times that of evaluating , regardless of the dimension. It's what PyTorch, JAX and TensorFlow do.
  • Gradient checking. If you derive it by hand, compare it with central differences with ; a relative error of or less is correct, is a bug.
  • Finding η. Try values on a log scale () for a few iterations; the good one is usually an order of magnitude below the one that diverges.
  • Gradient clipping. Capping keeps an anomalous batch from flinging the parameters far away (common in recurrent networks and transformers).
  • Early stopping. Monitor the validation loss and keep the best point; continuing to push down the training loss can overfit.

§9 · Implementation

SGD, Adam and gradient checking in NumPy

optim.py · verified: SGD ends 0.02 from the exact solution (noise floor), Adam 1e-15, grad_check 1e-10

import numpy as np

def sgd(X, y, eta=0.05, batch=32, epochs=20, seed=0):
    rng = np.random.default_rng(seed)
    n, p = X.shape
    w = np.zeros(p)
    for epoch in range(epochs):
        idx = rng.permutation(n)                          # shuffle every epoch
        for s in range(0, n, batch):
            b = idx[s:s + batch]
            g = 2 / len(b) * X[b].T @ (X[b] @ w - y[b])   # mini-batch gradient (MSE)
            w -= eta * g
    return w

def adam(grad, w0, eta=1e-3, b1=0.9, b2=0.999, eps=1e-8, steps=1000):
    w = w0.astype(float).copy()
    m = np.zeros_like(w); v = np.zeros_like(w)
    for t in range(1, steps + 1):
        g = grad(w)
        m = b1 * m + (1 - b1) * g                         # moving average of the gradient
        v = b2 * v + (1 - b2) * g * g                     # moving average of the squared gradient
        m_hat = m / (1 - b1 ** t)                         # bias correction
        v_hat = v / (1 - b2 ** t)
        w -= eta * m_hat / (np.sqrt(v_hat) + eps)
    return w

def grad_check(f, grad, w, h=1e-6):
    num = np.array([(f(w + h * e) - f(w - h * e)) / (2 * h) for e in np.eye(len(w))])
    return np.max(np.abs(num - grad(w))) / max(1e-12, np.max(np.abs(num)))

In scikit-learn, SGDRegressor and SGDClassifier implement SGD with step schedules (learning_rate="invscaling" by default for regression) and support partial_fit for incremental learning. In neural networks the pattern is always the same: optimizer.zero_grad(), loss.backward(), optimizer.step().

§10 · Checklist

Before you blame the model

  • Standardize the features. It's the cheapest way to lower .
  • Check the gradient with finite differences if you're not using autodiff.
  • If the loss goes up or gives nan: is too large (or the data has extreme values). Divide by 10.
  • If it goes down very slowly and smoothly: is small or the problem is ill-conditioned. Raise , add momentum or scale.
  • If it stalls with noise: that's the SGD floor. Lower with a schedule or increase the batch.
  • Shuffle the data every epoch; sorted data biases the batches.
  • Measure the loss on validation, not just on training.

fuel_gd.py · reproduces the numbers above

import numpy as np

x = np.array([5, 10, 15, 20.])          # load (t)
y = np.array([28, 31, 35, 37.])         # fuel use (L/100 km)

def gd(X, y, eta, tol=1e-3, max_iter=100_000):
    w = np.zeros(X.shape[1])
    for t in range(max_iter):
        g = 2 / len(y) * X.T @ (X @ w - y)
        if np.abs(g).max() < tol:
            return w, t
        w -= eta * g
    return w, max_iter

raw = np.column_stack([np.ones(4), x])
print(np.linalg.eigvalsh(2 / 4 * raw.T @ raw))       # [0.332 376.668] -> kappa = 1135
print(gd(raw, y, eta=0.004))                         # (array([24.997, 0.620]), 6789)

u = (x - 12.5) / 5
scaled = np.column_stack([np.ones(4), u])
w, it = gd(scaled, y, eta=0.4)
print(w, it)                                         # [32.75 3.1] 7
print(w[1] / 5, w[0] - w[1] / 5 * 12.5)              # 0.62 25.0

What would change in a real system

  • Millions of trips and many features (grade, speed, temperature, vehicle type): same scheme with mini-batches and Adam or SGD with momentum.
  • Stable scaling statistics: the mean and standard deviation used for scaling are computed once (or with moving averages) and versioned with the model; if they change every night, the coefficients aren't comparable.
  • Robustness to bad data: a sensor reporting 400 L/100 km can ruin a step; use Huber loss or gradient clipping.
  • Drift: with a constant η the model slowly "forgets" old data, which is useful if the fleet changes (new vehicles, seasons of the year).
