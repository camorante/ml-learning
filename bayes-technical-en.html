Bayes, for programmers

The theorem in probability form and in betting-odds form, parameter inference with conjugate priors, why the posterior mean is an average that "shrinks" toward the prior, and Naive Bayes as a generative classifier: when it works and why its probabilities come out too extreme. With code verified against scikit-learn and an example worked out by hand.

Summary

  • Posterior ∝ likelihood × prior. In odds form: , and in log-odds independent clues add up.
  • With a conjugate prior the posterior has closed form: Beta-Binomial, Gamma-Poisson, Normal-Normal. The last one is exactly the Kalman filter update.
  • The posterior mean is a weighted average of the prior mean and the data mean. With little data the prior dominates (shrinkage); with lots of data, the data does.
  • Naive Bayes models : it trains in and needs little data, but with correlated features it counts the evidence several times and its probabilities become extreme.
prior→ likelihood→ posterior→ predictive→ decision→ calibrate

§4 · Classifier

Naive Bayes

A generative classifier models and and applies Bayes. Naive Bayes assumes the features are independent within each class:

  • Gaussian: . Training means computing means and variances per class.
  • Multinomial (counts: words in a maintenance shop note, events per trip): , with . Laplace smoothing keeps an unseen word from wiping out the class.
  • Bernoulli: presence or absence of each signal, and absence also provides evidence.

Everything is computed in logarithms and normalized with log-sum-exp. With variances shared across classes, the boundary is linear, the same family as logistic regression. The difference is in how it's fit: Ng and Jordan (2002) showed that the generative model reaches its final error sooner (it needs examples versus ), but that error is usually higher than the discriminative one's with lots of data.

The price of "naive." With two Gaussian features with correlation within each class and means equally separated in both, the Naive Bayes boundary matches the optimal one, but its logit is times the true one: it counts the shared evidence twice. It's just as accurate, but its probabilities stick to 0 and 1. The widget compares the two curves along the direction that separates the classes.

§5 · Deciding

From the posterior to the decision

The posterior is not the decision. With costs (taking a healthy truck out of service) and (letting a broken one keep running), the optimal choice is to act when

If an undetected breakdown costs 20 times as much as an unnecessary inspection, it pays to inspect from up: with the alert from the example (27%), inspecting is the right decision even though the truck is most likely healthy. That's why the probabilities have to be calibrated: 27% must mean that 27 out of every 100 such cases are breakdowns. Naive Bayes rarely meets that without recalibration (isotonic or Platt, §8).

§6 · Beyond

When there is no closed form

  • MCMC (Metropolis, Hamiltonian Monte Carlo, NUTS in Stan or PyMC): samples from the posterior of any model, for example a hierarchical regression of fuel consumption by driver, truck and route.
  • Variational inference: approximates the posterior with a simple distribution by optimizing, and scales better than MCMC at the cost of exactness.
  • Laplace approximation: a Gaussian at the MAP. Bayesian logistic regression and Gaussian process classification use it.
  • Bayesian optimization: a Gaussian process over the function "hyperparameters → validation error," useful for tuning XGBoost with few trials.
  • Informative priors: always check them with prior predictive simulations (what data does the prior generate?) and analyze the sensitivity to them.

§7 · Implementation

Bayes and Naive Bayes from scratch

mybayes.py · verified: GaussianNB matches sklearn on breast_cancer and iris (probabilities to 2·10⁻¹⁵, same predictions); MultinomialNB matches on digits (3·10⁻¹³); posterior(0.02, 0.9, 0.05) = 0.2687, same as a simulation of 2 million trucks (0.2679); beta_summary(5, 10) matches scipy

import numpy as np
from scipy.special import logsumexp, betaln

# ---------- Bayes' theorem ----------
def posterior(prior, sens, fpr):
    """P(breakdown | alert) with prior = P(breakdown), sens = P(alert | breakdown), fpr = P(alert | healthy)."""
    num = prior * sens
    return num / (num + (1 - prior) * fpr)

# ---------- Proportion with a Beta prior (conjugate) ----------
def beta_update(a, b, exitos, fracasos):
    """Beta(a, b) + binomial data -> Beta(a + successes, b + failures)."""
    return a + exitos, b + fracasos

def beta_summary(a, b):
    from scipy.stats import beta
    return a / (a + b), beta.ppf([0.05, 0.95], a, b)        # mean and 90% credible interval

def log_evidence(a, b, k, n):
    """log P(data) under Beta-Binomial (without the binomial coefficient): useful for comparing priors."""
    return betaln(a + k, b + n - k) - betaln(a, b)

# ---------- Naive Bayes ----------
class GaussianNB:
    def fit(self, X, y, var_smoothing=1e-9):
        self.classes_ = np.unique(y)
        self.theta_ = np.array([X[y == c].mean(0) for c in self.classes_])
        eps = var_smoothing * X.var(0).max()                  # same as sklearn: avoids zero variances
        self.var_ = np.array([X[y == c].var(0) for c in self.classes_]) + eps
        self.log_prior_ = np.log(np.array([(y == c).mean() for c in self.classes_]))
        return self

    def joint_log_likelihood(self, X):
        # log P(c) + sum_j log N(x_j | mu_cj, var_cj): the "naive" product becomes a sum
        ll = -0.5 * (np.log(2 * np.pi * self.var_)[None] + (X[:, None, :] - self.theta_[None]) ** 2 / self.var_[None]).sum(2)
        return ll + self.log_prior_

    def predict_proba(self, X):
        jll = self.joint_log_likelihood(X)
        return np.exp(jll - logsumexp(jll, axis=1, keepdims=True))   # normalize in log space

    def predict(self, X):
        return self.classes_[self.joint_log_likelihood(X).argmax(1)]

class MultinomialNB:
    """For counts (events per trip, words per maintenance shop note). alpha: Laplace smoothing."""
    def fit(self, X, y, alpha=1.0):
        self.classes_ = np.unique(y)
        counts = np.array([X[y == c].sum(0) for c in self.classes_]) + alpha
        self.feature_log_prob_ = np.log(counts / counts.sum(1, keepdims=True))
        self.log_prior_ = np.log(np.array([(y == c).mean() for c in self.classes_]))
        return self

    def predict_proba(self, X):
        jll = X @ self.feature_log_prob_.T + self.log_prior_
        return np.exp(jll - logsumexp(jll, axis=1, keepdims=True))

§8 · In production

With libraries: accuracy versus calibration

nb_calibracion.py · actual output in the comments (scikit-learn 1.9)

import numpy as np
from sklearn.datasets import load_breast_cancer
from sklearn.model_selection import train_test_split
from sklearn.naive_bayes import GaussianNB
from sklearn.linear_model import LogisticRegression
from sklearn.pipeline import make_pipeline
from sklearn.preprocessing import StandardScaler
from sklearn.calibration import CalibratedClassifierCV
from sklearn.metrics import accuracy_score, brier_score_loss, log_loss

X, y = load_breast_cancer(return_X_y=True)                     # 569 cases, 30 highly correlated features
Xtr, Xte, ytr, yte = train_test_split(X, y, test_size=0.3, stratify=y, random_state=0)

modelos = {
    "Naive Bayes": GaussianNB(),
    "NB calibrated": CalibratedClassifierCV(GaussianNB(), method="isotonic", cv=5),
    "logistic": make_pipeline(StandardScaler(), LogisticRegression(max_iter=5000)),
}
for nombre, m in modelos.items():
    p = m.fit(Xtr, ytr).predict_proba(Xte)[:, 1]
    seguro = np.mean((p < 0.01) | (p > 0.99))
    print(f"{nombre:13s} accuracy {accuracy_score(yte, p > 0.5):.3f}  Brier {brier_score_loss(yte, p):.3f}  "
          f"log-loss {log_loss(yte, np.clip(p, 1e-15, 1 - 1e-15)):.3f}  cases with p<1% or >99%: {seguro:.0%}")
# Naive Bayes   accuracy 0.924  Brier 0.076  log-loss 1.081  cases with p<1% or >99%: 95%
# NB calibrated accuracy 0.918  Brier 0.061  log-loss 0.575  cases with p<1% or >99%: 81%
# logistic      accuracy 0.959  Brier 0.026  log-loss 0.085  cases with p<1% or >99%: 72%

# counting the same clue twice: duplicating the columns hurts the confidence, not the accuracy
nb2 = GaussianNB().fit(np.hstack([Xtr, Xtr]), ytr)
p2 = nb2.predict_proba(np.hstack([Xte, Xte]))[:, 1]
print(f"NB with duplicated columns: accuracy {accuracy_score(yte, p2 > 0.5):.3f}  log-loss {log_loss(yte, np.clip(p2, 1e-15, 1 - 1e-15)):.3f}")
# NB with duplicated columns: accuracy 0.924  log-loss 1.500

Naive Bayes is 92% accurate, but it claims to be almost certain (below 1% or above 99%) in 95% of cases, and when it's wrong it is wrong with a confidence that sends the log-loss soaring. Recalibrating it greatly improves its probabilities while barely changing the accuracy. Duplicating the columns leaves the accuracy unchanged and worsens the log-loss: that's idea 4 of the simple version, measured. With 30 highly correlated features, logistic regression is clearly better. Naive Bayes shines with text, with high-dimensional counts and when there is very little data.

§9 · Checklist

Before trusting your Bayesian math

  • The correct base rate for the population where it's applied (not the training set's if the classes were rebalanced).
  • Evidence that is really independent before multiplying likelihood ratios.
  • A justified prior and checked sensitivity: does the conclusion change with a different reasonable prior?
  • Calibrated probabilities before using them in a decision threshold.
  • Smoothing (Laplace or Dirichlet) for unseen categories or words.
  • A threshold chosen from the cost of each error, not the default 50%.

Is the breakdown alert real?

  1. Count 1,000 trucks

    In words

    We imagine a fleet of 1,000 trucks and split it according to the data. Reasoning with whole numbers is much easier than with percentages of percentages.

    The math

    Why 1,000 and not some other number?

    It doesn't matter: the final result doesn't depend on the size of the imaginary fleet. We pick 1,000 because with 2% it gives a whole number of broken trucks (20). This way of counting is called "natural frequencies," and it has been shown that with it almost everyone reasons correctly about these problems (Gigerenzer and Hoffrage, 1995).

  2. How many alerts will there be?

    In words

    Alerts come from two groups: the broken trucks the system detects and the healthy ones it gets wrong.

    The math

    What it means: even though the system is wrong on only 5% of the healthy trucks, there are so many healthy ones that this 5% (49 trucks) outnumbers all the detected broken ones (18).

  3. The probability of a breakdown after the alert

    In words

    If our truck raised an alert, it's one of those 67. What fraction of them really has a failure?

  4. The same calculation in odds

    In words

    Odds are "how many for, per one against," as in betting. Their advantage is that the clue is applied with a single multiplication.

    The math

    Where does the 18 come from?

    It's the likelihood ratio: an alert is 18 times more likely on a broken truck (90%) than on a healthy one (5%). It's a property of the sensor and doesn't depend on how many trucks are broken. That's why it's worth keeping it separate from the prior.

    In words

    A second, independent system with the same precision also raises an alert. What we believed after the first one (18:49) is now the starting point, and it gets multiplied by 18 again.

    The math

    If instead of an alert there were an inspection without an alert, the clue would be "no alert": . From the initial 2%:

    Why 0.10 and 0.95?

    They are the complementary probabilities: if the system alerts on 90% of broken trucks, it stays silent on 10%; if it gives a false alarm on 5% of healthy ones, it stays silent on 95%. An alert that doesn't go off is information too.

    What it means: two independent alerts already make a breakdown very likely (87%). A clean inspection leaves it at 0.2%, ten times less than before looking. The key word is independent: if both systems fail for the same reason, the second alert is worth much less (idea 4 of the simple version).

    In words

    A new driver has done 5 trips and 3 arrived late. The direct count says 60%, but with 5 trips that's very unreliable. We start from what we know about the fleet and add their trips to it.

    The 90% credible interval runs from 15% to 54%.

    In words

    A 27% probability doesn't say whether to act: that depends on what it costs to be wrong in each direction (§5).

alerta_bayes.py · reproduces the numbers above

from mybayes import posterior, beta_update, beta_summary

p1 = posterior(0.02, 0.90, 0.05)          # one alert
p2 = posterior(p1, 0.90, 0.05)            # second independent alert
p0 = posterior(0.02, 0.10, 0.95)          # inspection with no alert: P(no alert | breakdown) = 0.10
print(round(p1, 4), round(p2, 4), round(p0, 4))   # 0.2687 0.8686 0.0021

a, b = beta_update(2, 8, exitos=3, fracasos=2)  # fleet prior + the driver's 5 trips (exitos = late, fracasos = on time)
print(a, b, beta_summary(a, b))           # 5 10 (0.333, [0.153 0.540])

What would change in a real system

  • Base rate per segment: the failure is more common in trucks with more miles on them. The prior should depend on the vehicle (for example, via a logistic regression).
  • Measured sensitivity and false positives from real inspections, with their own confidence intervals.
  • Non-independent sensors: if two alerts share the cause of the error, the second one is worth less than ×18.
  • Fleet prior estimated from data (empirical Bayes) instead of chosen by hand.
