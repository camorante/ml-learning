Convolutional networks, for programmers

Discrete convolution (which in libraries is a cross-correlation), with stride, padding and channels, and the output-size formula; the convolutional layer as a dense layer with a Toeplitz matrix; pooling and receptive field; backpropagation through shared weights; conv1d, conv2d and max-pooling from scratch in NumPy, verified against PyTorch; and a real training run of a 1D CNN versus a dense network to detect harsh braking in a truck's accelerometer, with the experiment of shifting the event. With a worked example: one filter over one second of signal, by hand.

Summary

  • A convolutional layer is a dense layer whose matrix has the same filter in every row, shifted: with 64 readings and a filter of 5, 3,840 matrix entries shrink to 5 parameters, and the layer commutes with shifts.
  • On 1,000 accelerometer test windows, a 1D CNN with 201 parameters gets 96.3% right and a dense network with 2,113 gets 88.8% (over three seeds: 95.8–96.3% versus 88.8–90.3%).
  • Trained with the braking always at the start of the window and tested with it at the end, the dense network drops to 46.1% (it says "no" to everything) and the CNN stays at 96.7%.
  • The weight gradient is the correlation of the input with the output gradient; the input gradient is the full convolution of that gradient with the filter. Our conv1d, conv2d and max-pooling in NumPy match PyTorch to within .

§1 · The problem

A dense layer does not know the signal has an order

A dense layer from topic 3 over a window of readings has weights and treats the readings as an unordered set: permuting the inputs (and the columns of ) gives the same network. Two properties of signals and images are lost:

  • Locality. What defines a braking is a few consecutive readings; distant readings hardly matter for recognizing it.
  • Stationarity. The shape of a braking does not depend on when it happens. The dense layer learns a different detector for each position, each one from the examples that fall on it.

Convolution imposes both: weights only for a neighborhood of readings, and the same weights at every position. The result is shift-equivariant: if , then (except at the edges). A global max over positions turns this into invariance: the output does not change if the event moves.

§2 · Definition

Cross-correlation, stride, padding and channels

For an input with channels and length , a layer with filters of size , stride and padding computes, for each filter and output position :

Each term is a dot product (math topic 2) between the filter and a slice of the input. The layer has parameters, independent of . With and (padding="same" in PyTorch) the output is as long as the input; with , half as long. Dilation uses and widens the field with no extra weights (Dumoulin and Visin, 2016, cover all of this arithmetic).

In mathematics, convolution flips the filter: . What torch.nn.Conv1d and almost every library implement is the cross-correlation above, without the flip. For a network it makes no difference (the learned filter would be the same, reversed), but it matters when loading filters from another source or comparing with np.convolve: check.py checks it in §5.

conv.py · conv1d, conv2d and max-pooling from scratch, forward and backward

"""1D and 2D convolution (with stride, padding and channels) and 1D max-pooling from scratch in NumPy, forward and
backward. Like PyTorch, it is a cross-correlation: the filter is NOT flipped."""
import numpy as np


def ventanas1d(L, k, s):
    """Window indices: row i = positions s·i, s·i+1, …, s·i+k−1 of the (already padded) input."""
    n_out = (L - k) // s + 1
    return s * np.arange(n_out)[:, None] + np.arange(k)              # (n_out, k)


def conv1d(x, W, b, s=1, p=0):
    """x: (n, C, L) · W: (F, C, k) · b: (F,) → y: (n, F, ⌊(L + 2p − k)/s⌋ + 1)."""
    xp = np.pad(x, ((0, 0), (0, 0), (p, p)))
    idx = ventanas1d(xp.shape[2], W.shape[2], s)
    trozos = xp[:, :, idx]                                            # (n, C, n_out, k)
    y = np.einsum("ncok,fck->nfo", trozos, W) + b[None, :, None]
    return y, (x.shape, xp.shape, idx, trozos, W, p)


def conv1d_atras(dy, cache):
    """dy = ∂loss/∂y. Returns ∂/∂x, ∂/∂W, ∂/∂b. Each weight is used at every position: its gradients add up."""
    xshape, xpshape, idx, trozos, W, p = cache
    dW = np.einsum("nfo,ncok->fck", dy, trozos)                       # correlation of the input with dy
    db = dy.sum((0, 2))
    dtrozos = np.einsum("nfo,fck->ncok", dy, W)
    dxp = np.zeros(xpshape)
    np.add.at(dxp, (slice(None), slice(None), idx), dtrozos)          # each reading receives from all its windows
    return dxp[:, :, p:xpshape[2] - p], dW, db


def conv2d(x, W, b, s=1, p=0):
    """x: (n, C, H, A) · W: (F, C, kh, ka) → y: (n, F, H', A'), the same size formula on each axis."""
    xp = np.pad(x, ((0, 0), (0, 0), (p, p), (p, p)))
    ih, ia = ventanas1d(xp.shape[2], W.shape[2], s), ventanas1d(xp.shape[3], W.shape[3], s)
    trozos = xp[:, :, ih[:, None, :, None], ia[None, :, None, :]]     # (n, C, H', A', kh, ka)
    y = np.einsum("ncijab,fcab->nfij", trozos, W) + b[None, :, None, None]
    return y, (xp.shape, ih, ia, trozos, W, p)


def conv2d_atras(dy, cache):
    xpshape, ih, ia, trozos, W, p = cache
    dW = np.einsum("nfij,ncijab->fcab", dy, trozos)
    db = dy.sum((0, 2, 3))
    dxp = np.zeros(xpshape)
    np.add.at(dxp, (slice(None), slice(None), ih[:, None, :, None], ia[None, :, None, :]),
              np.einsum("nfij,fcab->ncijab", dy, W))
    return dxp[:, :, p:xpshape[2] - p, p:xpshape[3] - p], dW, db


def maxpool1d(x, k=2, s=None):
    """Maximum of each window of k readings (by default, non-overlapping: stride s = k)."""
    s = s or k
    idx = ventanas1d(x.shape[2], k, s)
    trozos = x[:, :, idx]                                             # (n, C, n_out, k)
    arg = trozos.argmax(-1)
    return np.take_along_axis(trozos, arg[..., None], -1)[..., 0], (x.shape, idx, arg)


def maxpool1d_atras(dy, cache):
    """The gradient only flows through the reading that won each window; the others get 0."""
    xshape, idx, arg = cache
    dx = np.zeros(xshape)
    n, C, n_out = dy.shape
    gan = idx[np.arange(n_out)[None, None, :], arg]                   # winning position of each window
    np.add.at(dx, (np.arange(n)[:, None, None], np.arange(C)[None, :, None], gan), dy)
    return dx

The trick is to build the indices of all the windows at once (ventanas1d): xp[:, :, idx] gives a tensor with every slice, and the whole layer is one einsum. This is the idea behind im2col, which libraries use to turn convolution into a matrix product.

§3 · As a matrix

A convolution is a dense layer with a Toeplitz matrix

For one channel, stride 1 and no padding, with if and 0 otherwise: an matrix that is constant along each diagonal (a Toeplitz matrix), a linear transformation like the ones in math topic 3. Compared with a dense layer of the same shape, convolution fixes almost all weights to zero and ties the rest together. With stride , one row in every is kept; with several channels, becomes a block matrix.

§4 · Pooling and receptive field

Shrink, tolerate shifts and see farther

Max-pooling of size and stride (usually ) is ; average pooling replaces the max with the mean. It has no parameters, divides the length by and makes the output nearly invariant to shifts smaller than the slice. The global max answers "does shape appear anywhere?" and gives the head a fixed-size vector, whatever is.

§5 · Backward

Backpropagation through shared weights

With the gradient coming from above, the chain rule of topic 5 sums over every place where each weight is used:

  • The weight gradient is a correlation. With , : the cross-correlation of the input with . A weight shared by 60 positions receives the sum of 60 pushes; that is why a filter learns from each window many times.
  • The input gradient is a full convolution. with padding (that is, ): a transposed convolution. In conv1d_atras, np.add.at spreads each slice back to the readings that formed it.
  • Max-pooling. The gradient passes whole to the position that won each window and is 0 at the others (with ties, PyTorch picks one).

import torch
import torch.nn.functional as Fn

err = lambda a, t: float(np.max(np.abs(a - t.detach().numpy())))
print(f"PyTorch {torch.__version__}, float64 · maximum absolute error")


def prueba1d(n, C, L, F, k, s, p):
    x, W, b = rng.normal(size=(n, C, L)), rng.normal(size=(F, C, k)), rng.normal(size=F)
    y, cache = conv1d(x, W, b, s, p)
    dy = rng.normal(size=y.shape)                                     # an arbitrary gradient "from above"
    dx, dW, db = conv1d_atras(dy, cache)
    xt, Wt, bt = (torch.tensor(a, requires_grad=True) for a in (x, W, b))
    yt = Fn.conv1d(xt, Wt, bt, stride=s, padding=p); (yt * torch.tensor(dy)).sum().backward()

§6 · Real comparison

1D CNN versus dense network on the accelerometer

Windows of 64 readings (10 Hz, 6.4 s) of longitudinal acceleration in m/s². Each one has a braking with depth uniform between 1 and 5.5 m/s² and variable duration, with probability 0.6 a pothole (two readings, and , with between 2.5 and 5) and with 0.4 a speed-up. The label comes from the clean signal (in a real fleet, from the CAN bus speed): harsh if the 5-reading moving average drops below m/s². The network sees the signal with Gaussian noise of . Applying the rule as-is to the noisy signal gets 96.7% right on validation; looking only at the lowest reading, 72.8%.

Two datasets. A: the braking starts anywhere (2,000 for training, 1,000 for validation, 1,000 for test). B: as with a device that only records when it detects a braking, it starts between readings 2 and 20; it is tested on 1,000 windows where it starts between 38 and 57. Both networks are trained the same way: Adam with rate 0.01, batches of 32, 40 epochs, binary cross-entropy (topic 4, topic 6), in PyTorch with float64 and fixed seeds.

modelos.py · the networks and the training loop

"""The topic's three networks, in PyTorch, and a training loop with fixed seeds (Adam, batches of 32)."""
import numpy as np
import torch
from torch import nn

torch.set_default_dtype(torch.float64)


class CNN(nn.Module):
    """conv 1→4 (5) · ReLU · max-pool 2 · conv 4→8 (5) · ReLU · global max · linear 8→1."""
    def __init__(s):
        super().__init__()
        s.c1, s.c2, s.out = nn.Conv1d(1, 4, 5), nn.Conv1d(4, 8, 5), nn.Linear(8, 1)

    def mapas(s, x):                                   # x: (n, 64) → layer-1 maps (n, 4, 60)
        return torch.relu(s.c1(x[:, None, :]))

    def forward(s, x):
        h = nn.functional.max_pool1d(s.mapas(x), 2)    # (n, 4, 30)
        h = torch.relu(s.c2(h))                        # (n, 8, 26)
        return s.out(h.amax(-1))[:, 0]                 # logit of "harsh braking"


class Densa(nn.Module):
    """linear 64→32 · ReLU · linear 32→1: one weight for each reading and neuron."""
    def __init__(s, m=32):
        super().__init__()
        s.net = nn.Sequential(nn.Linear(64, m), nn.ReLU(), nn.Linear(m, 1))

    def forward(s, x):
        return s.net(x)[:, 0]


class UnFiltro(nn.Module):
    """The toy's network: one 5-weight filter · global max · linear 1→1 (no ReLU: the max already decides)."""
    def __init__(s):
        super().__init__()
        s.c, s.out = nn.Conv1d(1, 1, 5), nn.Linear(1, 1)

    def forward(s, x):
        return s.out(s.c(x[:, None, :]).amax(-1))[:, 0]


def n_param(m):
    return sum(p.numel() for p in m.parameters())


def entrenar(modelo, X, y, Xv, yv, epocas=40, lr=0.01, lote=32, seed=0):
    """Adam, binary cross-entropy. Returns the model and the curves (validation loss and accuracy per epoch)."""
    torch.manual_seed(seed)
    m = modelo()
    opt = torch.optim.Adam(m.parameters(), lr=lr)
    X, y, Xv, yv = (torch.tensor(a, dtype=torch.float64) for a in (X, y, Xv, yv))
    g = torch.Generator().manual_seed(seed + 1)
    perd = nn.functional.binary_cross_entropy_with_logits
    curva = []
    for _ in range(epocas):
        orden = torch.randperm(len(y), generator=g)
        for k in range(0, len(y), lote):
            j = orden[k:k + lote]
            opt.zero_grad(); perd(m(X[j]), y[j]).backward(); opt.step()
        with torch.no_grad():
            z = m(Xv); curva.append((perd(z, yv).item(), ((z > 0).double() == yv).double().mean().item()))
    return m, curva


def acierto(m, X, y):
    with torch.no_grad():
        return float(((m(torch.tensor(X)) > 0).numpy() == np.asarray(y)).mean())


def prob(m, X):
    with torch.no_grad():
        return torch.sigmoid(m(torch.tensor(np.atleast_2d(X)))).numpy()

§8 · In two dimensions

Images: the same computation on each axis

The size formula applies to each axis separately (check.py: 16×16 with a 3×3 filter gives 14×14, and with stride 2 and padding 1, 8×8), and the parameters are . On a 224×224 color image, 64 dense neurons would need 9,633,856 weights; 64 filters of 3×3, 1,792. That difference is what made vision with neural networks possible:

  • Neocognitron (Fukushima, 1980): alternating layers of local detectors and pooling, inspired by the visual cortex.
  • LeNet-5 (LeCun et al., 1998): convolution, subsampling and end-to-end backpropagation to read digits and checks.
  • AlexNet (Krizhevsky et al., 2012): ReLU, dropout and GPUs; it won ImageNet by a huge margin.
  • VGG (Simonyan and Zisserman, 2015): only stacked 3×3 filters; two 3×3 filters see the same as one 5×5 with fewer weights.
  • ResNet (He et al., 2016): residual connections to train more than 100 layers.

In time series, the 1D CNN is a fast, parallelizable alternative to recurrent networks (topic 9): it sees fixed-length slices, while a recurrent network reads the sequence step by step with memory.

§9 · Checklist

Before using a CNN

  • Can the shape you are looking for appear at any position? If position matters, add it as an input or do not use a global max.
  • Compute the receptive field of the last layer and compare it with the duration of the event.
  • Check the sizes with at every layer; one stride or pooling too many leaves the signal at 0.
  • When loading filters from elsewhere, remember that PyTorch does cross-correlation (without flipping the filter).
  • Test with events at positions that were not in the training data: it is the test that separates the CNN from the dense network.
  • Train with several seeds: small networks with a global max can get stuck.
  • Verify your own implementations against torch.nn.functional, including the gradients and the cases with stride and padding.

§10 · Worked example

One filter over one second of braking, by hand

The "harsh braking" window from the toy in the simple version, with its learned filter.

The situation. A truck brakes in validation window no. 200. We take one second of its accelerometer, readings 33 to 42 (from 3.3 to 4.2 s): −3.94, −3.80, −4.18, −4.30, −4.64, −4.90, −2.95, −1.90, −0.64 and 0.63 m/s². The filter has 5 weights: −0.45, −0.40, −0.45, −0.34 and −0.39. What is each filter sum, what does a max-pooling of 2 leave, and does the alert go off?

Example map

We place the filter over the 10 readings at the 6 positions where it fits, compute each sum, keep the maximum of each pair (max-pooling of 2) and compare the largest with the alert threshold. At the end we see why that threshold is, deep down, the fleet's rule.

  1. The constants: where each number comes from.
  2. Outputs 33 and 34: the filter in the middle of the braking.
  3. Outputs 35 and 36: the recovery starts to come in.
  4. Outputs 37 and 38: the braking ends.
  5. Max-pooling of 2 and the decision.
  6. Why the threshold is the 3 m/s² rule.

  1. The constants: where each number comes from

    In words

    Each filter output is a sum of 5 products: weight times reading. Output uses readings to . With 10 readings and a filter of 5, stride 1 and no padding, the size formula gives outputs, from 33 to 38.

    The math

    symbolvaluewhat it is
    m/s²reading of the longitudinal accelerometer; it measures 10 times per second, so reading 33 is the instant 3.3 s into the window. Negative = the truck is braking
    −0.45 … −0.39the 5 weights learned by the one-filter network (§6, seed 1), rounded to 2 decimals as in the toy; they have no units
    m/s²the filter output at position : one cell of the feature map
    6.03the alert threshold: of all possible thresholds, the one that gets the most windows right (195 of 200) with this filter on the toy's 200 windows (6.0296, rounded)
    5readingsthe filter size: half a second, the same as the fleet's rule

    What it means: the filter has no bias in the toy. The one-filter network does have one (−5.82), but adding it to every output does not change which one is largest, so it can be moved into the threshold.

  2. Outputs 33 and 34: the filter in the middle of the braking

    In words

    A negative weight times a negative reading gives a positive product. In the middle of the braking, the five products are around 1.5–1.9 and the sum goes above 8.

    The math

    Why does it go up from 33 to 34?

    Moving one reading forward, the filter drops −3.94 and picks up −4.90, the lowest reading in the stretch. The weights do not change: it is the same filter, shifted. That is the whole idea of shared weights.

    What it means: 8.8056 is the largest of the 60 outputs in the whole window, the one the toy marks as "largest: 8.81" at 3.4 s.

  3. Outputs 35 and 36: the recovery starts to come in

    In words

    From the right come −2.95 and −1.90: the truck stops braking so hard, and the last products get small.

    The math

    Where do those products come from?

    In the filter covers readings 35 to 39 (−4.18, −4.30, −4.64, −4.90 and −2.95): for example, . In , readings 36 to 40, and the last product is .

    What it means: the map goes down as the filter leaves the braking, although it is still well above the threshold.

  4. Outputs 37 and 38: the braking ends

    In words

    In come −0.64 and 0.63. A positive reading times a negative weight subtracts: the truck is already speeding up a little.

    The math

    Why does the last one subtract?

    It is . A filter with all weights negative rewards what is below zero and penalizes what is above it: a speed-up right after the braking would lower the sum.

    What it means: is still above 6.03; is not. Over the whole window, 11 of the 60 outputs exceed the threshold, all in a row, on top of the braking.

  5. Max-pooling of 2 and the decision

    In words

    We split the 6 outputs into 3 pairs and keep the larger one of each pair. Then the largest of the three is compared with the threshold.

    The math

    And if the braking had come one reading later?

    The 8.8056 would show up in output 35, which belongs to the second pair: the first pooled value would change, but the final maximum would be the same. Pooling halves the map and tolerates short shifts; the maximum over everything does not depend on where the braking is.

    What it means: alert. The fleet also says this window has a harsh braking: correct.

  6. Why the threshold is the 3 m/s² rule

    In words

    Since the five weights are similar, the filter sum is almost the mean of the 5 readings times the sum of the weights. Dividing by that sum brings the numbers back to m/s².

    The math

    Where does the 2.970 come from?

    Nobody told the network the fleet's rule (braking at more than 3 m/s² on average for half a second). Learning from 2,000 windows, the filter has turned into a half-second average, and the best threshold is equivalent to 2.97 m/s² of mean deceleration: the rule, recovered from the noisy accelerometer. The approximation is not exact because the weights are not equal: versus the actual mean .

    What it means: a 5-number filter, shifted across the whole window, does the rule's job at any moment of the trip. The full CNN in §6 combines 4 filters like this and then 8 more, and that is why it also tells potholes and speed-ups apart.

"""Worked example: the toy's filter over 10 readings (1 s) of the "harsh braking" window, each output by
hand; then a max-pooling of 2 and the decision with the toy's threshold."""
import json
import numpy as np


def suma(w, x, i):
    """One cell of the map, accumulated in the same order as the toy (JS) and toys.py."""
    a = 0.0
    for k in range(5):
        a += w[k] * x[i + k]
    return a


E = json.load(open("../embed.json", encoding="utf-8"))
w, umbral = E["presets"]["aprendido"], E["umbral"]["aprendido"]
x = E["trazas"]["brusca"]
ini = 33                                                  # reading 33 = 3.3 s from the start of the window
tramo = x[ini:ini + 10]
print(f"filter w = {w}   (sum {sum(w):.2f})   toy threshold {umbral:.4f}")
print(f"readings {ini}–{ini + 9} (m/s²): {tramo}")
salidas = []
for i in range(6):                                        # 10 readings, filter of 5, stride 1, no padding → 6 outputs
    prod = [w[k] * tramo[i + k] for k in range(5)]
    s = suma(w, tramo, i); salidas.append(s)
    print(f"output {ini + i} ({(ini + i) / 10:.1f} s): " + " ".join(f"{p:+.4f}" for p in prod) + f" = {s:.4f}")
pool = [max(salidas[j], salidas[j + 1]) for j in (0, 2, 4)]
print("max-pooling of 2:", [f"{v:.4f}" for v in pool], "→ the largest:", f"{max(pool):.4f}",
      "→", "ALERT" if max(pool) > umbral else "no alert")
mapa = [suma(w, x, i) for i in range(len(x) - 4)]
print(f"over the whole window: {len(mapa)} outputs, the largest {max(mapa):.4f} at position {int(np.argmax(mapa))};"
      f" {sum(v > umbral for v in mapa)} outputs exceed the threshold")
print(f"the fleet's rule in this half second: mean of readings {ini + 1}–{ini + 5} = {np.mean(x[ini + 1:ini + 6]):.3f} m/s²")
print(f"threshold / |sum of weights| = {umbral:.4f} / {abs(sum(w)):.2f} = {umbral / abs(sum(w)):.3f} m/s² of mean deceleration;"
      f"  largest sum / |sum| = {max(mapa) / abs(sum(w)):.3f} m/s²")

What would change in a real system

  • More axes and more sensors: lateral and vertical acceleration, gyroscope and speed enter as channels of the first layer ( instead of 1).
  • Many filters: 32 or 64 per layer, several layers and a softmax head to tell braking, turning, impact and pothole apart at once.
  • Sliding windows over the whole trip: the CNN is applied to the entire signal at once and the last layer's map says in which second each maneuver happens.
  • Noisy labels: here the label comes from a clean rule; with human labels, the accuracy ceiling drops.
