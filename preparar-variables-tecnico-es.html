Preparar variables, para programadores

Escalado y para qué modelos importa, transformaciones de forma, codificación de categorías (one-hot, ordinal, por la media del objetivo con suavizado y ajuste cruzado), variables cíclicas, agregados por ventanas de tiempo sin mirar al futuro y cómo encadenarlo todo en un Pipeline que se ajusta solo con el entrenamiento. Con un módulo desde cero idéntico a scikit-learn, 8 000 viajes simulados y un ejemplo resuelto a mano.

Resumen

  • Toda transformación con parámetros (medias, escalas, categorías, medias por categoría) es parte del modelo: se ajusta en entrenamiento y se aplica tal cual al resto.
  • Escalar importa en modelos basados en distancias, en penalizaciones y en el descenso de gradiente; no en árboles.
  • Categorías: one-hot si son pocas; con muchas, la media del objetivo suavizada hacia la global y calculada fuera de pliegue. Sin ajuste cruzado, el modelo aprende de una fuga.
  • Ciclos (hora, día, rumbo) en el círculo, con seno y coseno.
  • Ventanas de tiempo solo hacia atrás, con lo que realmente esté disponible en el momento de predecir.
tipos de columna→ ColumnTransformer→ modelo→ Pipeline.fit(train)→ predict(nuevo)

§1 · Escalar

Tres escaladores y cuándo hacen falta

con , (desviación con en el denominador), mínimo, máximo y cuartiles calculados en el entrenamiento. El primero es StandardScaler, el segundo MinMaxScaler y el tercero RobustScaler. Mínimo-máximo depende de dos valores extremos; el robusto, de la mitad central, así que un error de GPS no aplasta al resto.

Escalar cambia el resultado cuando el modelo:

  • mide distancias (k vecinos, k-means, SVM con núcleo RBF, procesos gaussianos con escala común): está dominada por la columna de mayor varianza;
  • penaliza coeficientes (Ridge, Lasso, logística con ): castiga más a la variable en unidades pequeñas, que necesita un grande;
  • se optimiza por gradiente: el número de condición de crece con la disparidad de escalas y el descenso zigzaguea.

Los árboles (y bosques y boosting) son invariantes a transformaciones monótonas de cada columna: escalar no cambia ninguna partición. Una regresión lineal sin penalización tampoco cambia sus predicciones, solo sus coeficientes.

§3 · Categorías

One-hot, ordinal y el número inventado

One-hot: la categoría se convierte en . Las columnas suman 1, colineales con el intercepto: en un modelo lineal sin penalización se quita una (drop="first"); con penalización o con árboles se pueden dejar todas. Una categoría desconocida (handle_unknown="ignore") queda como el vector cero. Ordinal (enteros) solo tiene sentido si hay un orden real y, en modelos lineales, si los saltos son aproximadamente iguales; para árboles es aceptable con pocas categorías, porque varias particiones pueden separar cualquier subconjunto.

En la flota, un modelo lineal con carga y tipo de camión como entero (orden alfabético) tiene un error absoluto medio de 6,17 L/100 km en la prueba; con one-hot, 3,43. Con grande y pocas filas por categoría, el one-hot da columnas casi vacías y no sirve para categorías nuevas: entran el hashing ( fijo, colisiones), la frecuencia de cada categoría y la codificación por la media del objetivo.

§4 · Muchas categorías

Codificación por la media: suavizado y ajuste cruzado

Cada categoría , con filas y media del objetivo , se sustituye por

que es la media posterior de un modelo jerárquico normal con (varianza dentro de la categoría entre varianza entre categorías). TargetEncoder(smooth="auto") estima ese cociente por categoría; con un número, es fijo (Micci-Barreca, 2001).

El problema es que contiene para cada fila de la categoría. Para un modelo flexible, esa columna es una fuga: en categorías pequeñas, está correlacionada con aunque la categoría no tenga ningún efecto. El ajuste cruzado lo corta: se divide el entrenamiento en pliegues y las filas de cada pliegue se codifican con medias calculadas en los demás. Para la prueba y producción se usan las medias de todo el entrenamiento. Es lo que hace TargetEncoder.fit_transform; ojo, fit(X).transform(X) no lo hace.

§7 · Desde cero

Escaladores, codificadores y ventanas verificados

prep.py

"""Preparar variables desde cero: escalar, codificar, ciclos y ventanas de tiempo."""
import numpy as np

class Estandarizar:
    """z = (x - media) / desviación (con ddof=0, como StandardScaler)."""
    def fit(self, X):
        X = np.asarray(X, float); self.media = X.mean(0); s = X.std(0); self.desv = np.where(s > 0, s, 1.0); return self
    def transform(self, X):
        return (np.asarray(X, float) - self.media) / self.desv

class MinMax:
    def fit(self, X):
        X = np.asarray(X, float); self.lo = X.min(0); r = X.max(0) - self.lo; self.rango = np.where(r > 0, r, 1.0); return self
    def transform(self, X):
        return (np.asarray(X, float) - self.lo) / self.rango

class Robusto:
    """(x - mediana) / rango intercuartílico: los atípicos no mueven la escala."""
    def fit(self, X):
        X = np.asarray(X, float); self.med = np.median(X, 0); q1, q3 = np.percentile(X, [25, 75], axis=0)
        iqr = q3 - q1; self.iqr = np.where(iqr > 0, iqr, 1.0); return self
    def transform(self, X):
        return (np.asarray(X, float) - self.med) / self.iqr

class UnaColumnaPorCategoria:
    """One-hot. Una categoría que no se vio al ajustar queda como todo ceros."""
    def fit(self, x, quitar_primera=False):
        self.cats = sorted(set(x)); self.cols = self.cats[1:] if quitar_primera else self.cats; return self
    def transform(self, x):
        pos = {c: j for j, c in enumerate(self.cols)}; M = np.zeros((len(x), len(self.cols)))
        for i, v in enumerate(x):
            if v in pos: M[i, pos[v]] = 1.0
        return M

def _medias_suavizadas(x, y, m):
    x = np.asarray(x); y = np.asarray(y, float); g = y.mean(); tab = {}
    for c in np.unique(x):
        yc = y[x == c]; tab[c] = (yc.sum() + m * g) / (len(yc) + m)     # n·media_c + m·global, entre n + m
    return tab, g

class MediaPorCategoria:
    """Codificación por la media del objetivo, suavizada hacia la media global con 'm' viajes ficticios.
    fit_transform usa ajuste cruzado: cada fila se codifica con medias calculadas SIN su pliegue."""
    def __init__(self, m=10.0): self.m = m
    def fit(self, x, y):
        self.tab, self.g = _medias_suavizadas(x, y, self.m); return self
    def transform(self, x):
        return np.array([self.tab.get(v, self.g) for v in x])
    def fit_transform(self, x, y, pliegues):
        x = np.asarray(x); out = np.empty(len(x))
        for tr, te in pliegues:
            tab, g = _medias_suavizadas(x[tr], np.asarray(y)[tr], self.m)
            out[te] = [tab.get(v, g) for v in x[te]]
        self.fit(x, y); return out

def ciclo(v, periodo):
    """Hora, día de la semana o mes como punto en un círculo: 23 h y 1 h quedan cerca."""
    a = 2 * np.pi * np.asarray(v, float) / periodo; return np.c_[np.sin(a), np.cos(a)]

def media_pasada(grupo, t, v, ventana):
    """Media de v en (t - ventana, t) para el mismo grupo, solo con filas ANTERIORES. NaN si no hay ninguna."""
    grupo = np.asarray(grupo); t = np.asarray(t, float); v = np.asarray(v, float); out = np.full(len(t), np.nan)
    for g in np.unique(grupo):
        idx = np.where(grupo == g)[0]; idx = idx[np.argsort(t[idx], kind="mergesort")]; tg = t[idx]; vg = v[idx]
        cs = np.r_[0, np.cumsum(vg)]
        lo = np.searchsorted(tg, tg - ventana, side="right"); hi = np.searchsorted(tg, tg, side="left")
        n = hi - lo; out[idx] = np.where(n > 0, (cs[hi] - cs[lo]) / np.maximum(n, 1), np.nan)
    return out

§8 · En la flota

8 000 viajes, todo en un Pipeline

Consumo en L/100 km de 8 000 viajes de 60 camiones en 240 días, con el tipo de camión, la carga, la distancia, la hora, el cliente (unos 1 300) y el desgaste de cada camión. Entrenamiento: días 0 a 160; prueba: 160 a 240.

variables_flota.py · salida real en los comentarios

import numpy as np
from sim import viajes                                       # simulador (incluido en la descarga)
from prep import ciclo, media_pasada
from sklearn.compose import ColumnTransformer
from sklearn.pipeline import make_pipeline
from sklearn.preprocessing import OneHotEncoder, TargetEncoder, FunctionTransformer
from sklearn.model_selection import KFold
from sklearn.ensemble import HistGradientBoostingRegressor
from sklearn.metrics import mean_absolute_error as MAE

d = viajes()
d["hist30"] = media_pasada(d.camion, d.dia, d.consumo, 30)   # solo viajes anteriores del mismo camión
tr = d.dia < 160                                               # separación temporal: 160 días / 80 días
d["hist30"] = d.hist30.fillna(d.consumo[tr].mean())          # sin historial: media del entrenamiento
prep = ColumnTransformer([
    ("tipo", OneHotEncoder(handle_unknown="ignore"), ["tipo"]),
    ("num", "passthrough", ["carga_t", "km", "hist30"]),
    ("hora", FunctionTransformer(lambda X: ciclo(np.asarray(X).ravel(), 24)), ["hora"]),
    ("cliente", TargetEncoder(smooth=10.0, target_type="continuous",
                              cv=KFold(5, shuffle=True, random_state=0)), ["cliente"]),
])
modelo = make_pipeline(prep, HistGradientBoostingRegressor(max_iter=300, learning_rate=0.05, random_state=0))
cols = ["tipo", "carga_t", "km", "hist30", "hora", "cliente"]
modelo.fit(d.loc[tr, cols], d.consumo[tr])                   # todo se ajusta SOLO con el entrenamiento
print(round(MAE(d.consumo[~tr], modelo.predict(d.loc[~tr, cols])), 3))     # 2.43
print(round(MAE(d.consumo[~tr], np.full((~tr).sum(), d.consumo[tr].mean())), 3))   # 9.248 (siempre la media)

§9 · Checklist

Antes de entrenar

  • Cada columna tiene un tipo decidido (cantidad, categoría, cíclica, fecha, identificador que no debe entrar).
  • Todas las transformaciones están dentro de un Pipeline, ajustado solo con el entrenamiento (y dentro de cada pliegue en la validación cruzada).
  • Escalado si el modelo usa distancias, penalizaciones o gradiente; robusto si hay atípicos.
  • Categorías desconocidas en producción manejadas explícitamente.
  • Medias por categoría suavizadas y con ajuste cruzado.
  • Ventanas solo hacia atrás, con el retraso real de llegada de cada dato.
  • El mismo código calcula las variables en entrenamiento y en producción (o un almacén de variables con consultas en un instante).
  • El Pipeline completo se guarda y versiona con el modelo.

§10 · Ejemplo resuelto

Tres viajes, dos clientes, dos horas y un camión

Distancias con y sin escalar, one-hot, medias suavizadas, el reloj y una ventana, a mano.

La situación. Un analista prepara las variables para estimar el consumo de un viaje nuevo: 20 km con 4 000 kg, de un cliente con un solo viaje en el histórico, saliendo a las 23:00 en un camión con cinco viajes en el último mes.

Mapa del ejemplo

Tres viajes, un cliente con un solo viaje, dos horas a ambos lados de la medianoche y cinco viajes de un camión. Con ellos calculamos a mano qué cambia al escalar, cómo se codifica un tipo de camión, cuánto se ajusta la media de un cliente, por qué la hora va en un círculo y qué viajes entran en una ventana de tiempo.

  1. ¿Qué viaje es más parecido, sin escalar?
  2. El mismo cálculo, escalado.
  3. Una columna por tipo de camión.
  4. La media ajustada de dos clientes.
  5. Las 23:00 y la 01:00 en un reloj.
  6. Una ventana que solo mira atrás.

  1. ¿Qué viaje es más parecido, sin escalar?

    Los datos

    Viajekmcarga (kg)
    A (el nuevo)204 000
    B1804 100
    C259 000

    En palabras

    La distancia entre dos viajes es la de toda la vida (Pitágoras) con las dos columnas tal cual.

    La cuenta

    Qué significa: B es "el más parecido" a A, aunque B recorre 9 veces más distancia y C es casi el mismo trayecto. Los 5 000 kg pesan más que los 160 km solo porque los kilos son números más grandes.

  2. El mismo cálculo, escalado

    En palabras

    Dividimos cada diferencia entre la desviación típica de su columna en la flota de entrenamiento: 60 km para la distancia y 3 000 kg para la carga. Así cada diferencia se mide en "desviaciones típicas" (restar la media no cambia las diferencias).

    La cuenta

    Qué significa: ahora C es el más parecido. Ni la respuesta anterior ni esta son "la verdad": escalar decide que una desviación típica de distancia y una de carga cuentan igual. Es una decisión mucho más razonable que dejar que la decidan las unidades.

  3. Una columna por tipo de camión

    La codificación (categorías en orden alfabético)

    Tipofrig.furg.ríg.tráil.
    rígido0010
    furgoneta0100
    (tipo nuevo)0000

    ¿Y la columna de sobra?

    Las cuatro columnas suman siempre 1, igual que la columna del término independiente de un modelo lineal. Sin penalización, el modelo no tiene una solución única: hay que quitar una columna (la categoría de referencia). Con penalización (Ridge, por ejemplo) o con árboles, se pueden dejar las cuatro. Un tipo que no se vio al entrenar queda como todo ceros: el modelo le da el valor de referencia.

  4. La media ajustada de dos clientes

    En palabras

    La media general de la flota es 25,0 L/100 km. Añadimos a cada cliente viajes ficticios con esa media.

    La cuenta

    Qué significa: el cliente de un viaje pasa de 8,1 a 23,5 (casi la media general); el de 185 viajes solo se mueve de 22,68 a 22,80. El peso de los datos propios es : 1/11 para el primero y 185/195 para el segundo.

  5. Las 23:00 y la 01:00 en un reloj

    La cuenta (ángulo = 2π · hora / 24)

    Qué significa: como números, las 23 y la 1 están a 22 de distancia y las 23 y las 11, a 12: al revés de la realidad. En el reloj, 23 h y 1 h están cerca (0,52, igual que 11 h y 13 h) y 23 h y 11 h, en lados opuestos (2, la máxima distancia).

  6. Una ventana que solo mira atrás

    Cinco viajes de un camión

    Día310182533
    L/100 km2830273129

    En palabras

    Para el viaje del día 33, la media de los 30 días anteriores usa los viajes con día entre 3 y 33, sin incluir ninguno de los dos extremos: el 3 queda justo en el borde y el 33 es el propio viaje.

    La cuenta

    Qué significa: la ventana centrada del día 25 incluye su propio consumo (31) y uno del futuro (29): el modelo ve la respuesta. El primer viaje del camión no tiene historial (queda vacío) y hay que rellenarlo, por ejemplo con la media de la flota en el entrenamiento.

Qué cambiaría en un sistema real

  • Escalas fijadas en el entrenamiento y guardadas con el modelo; nunca recalculadas con los datos del día.
  • Clientes nuevos: reciben la media general; conviene vigilar cuántos llegan.
  • Historial con retraso: si el consumo de un viaje se conoce al día siguiente, la ventana debe terminar ayer.
  • Más ventanas: 7 y 90 días, máximo, número de viajes, tendencia; cada una se valida igual.
