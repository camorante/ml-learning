Imbalanced classes, for programmers

Confusion-matrix metrics and which ones withstand prevalence, ROC and precision-recall curves with their baselines, the Bayes threshold from costs, what class weights and resampling (SMOTE included) really do, probability correction for prior shift, and calibration. With a from-scratch module identical to scikit-learn, 20,000 simulated truck-weeks and an example worked by hand.

Summary

  • With a small prevalence , the constant classifier has accuracy . Evaluate with precision, recall, the PR curve and, above all, expected cost.
  • The ROC curve does not depend on ; the PR curve does, and its baseline is . With rare classes, PR better describes what the person receiving the alerts sees.
  • Class weights and resampling barely change the ordering of the scores (same AUC and AP on the fleet): mostly they shift the effective threshold and inflate the probabilities.
  • If you rebalance by a factor , correct the probabilities by dividing the odds by . Without correction, the cost threshold does worse than never alerting.
  • With few positives, every metric has high variance: stratified validation and confidence intervals.

§2 · Curves

ROC versus precision-recall

The ROC curve plots (FPR, TPR) for every threshold; its area (AUC) is the probability that a random positive scores higher than a random negative (the Mann-Whitney statistic). The baseline is the diagonal (AUC = 0.5). The PR curve plots (recall, precision), and its baseline is horizontal at . Its usual summary is average precision:

§4 · Rebalancing

Class weights, resampling and SMOTE

Weights: the loss is weighted, , with class_weight="balanced" = . For log-loss, multiplying the weight of the positives by is equivalent to multiplying their frequency by : the model estimates the odds of a world with prior such that . In a well-specified logistic regression, that amounts to adding to the intercept: the ordering of the scores doesn't change, only the effective threshold.

Resampling: oversampling positives (copies) or undersampling negatives has the same effect in expectation, with more variance (copies overfit; undersampling throws away information). SMOTE creates synthetic positives , , with one of the positive neighbors of : it smooths the positive region, but invents points that can land in negative zones and adds no new information.

Golden rule: all resampling goes inside cross-validation, only on the training fold (imblearn.pipeline.Pipeline). Resampling before splitting puts copies of the same positive in both training and test: leakage (topic 1).

When the model isn't calibrated by construction (boosted trees, SVMs, Naive Bayes), you recalibrate on a separate set: Platt (a logistic regression on the score) or isotonic (a monotone step function, needs more data), with CalibratedClassifierCV. With very few positives, isotonic overfits: prefer Platt.

§6 · Evaluation

Few positives, lots of variance

With positives in the test set, recall is a binomial proportion with standard error : with 23 breakdowns and , the 95% Wilson interval runs from 0.37 to 0.74. Recommendations:

  • Stratify every split (StratifiedKFold, stratify=y) so each fold gets its share of positives; with groups or time, StratifiedGroupKFold or make sure each time block has positives.
  • Pool out-of-fold predictions (cross_val_predict) and compute a single PR curve, instead of averaging the AP of folds with 5 positives.
  • Intervals via stratified bootstrap for AP and cost.
  • Choose the threshold on validation, not on the test set, and report the test cost with that threshold fixed.

§7 · From scratch

Metrics, curves and SMOTE, verified

imb.py

"""Metrics and techniques for imbalanced classes, from scratch."""
import numpy as np

def matriz(y, s, t):
    """True/false positives and negatives when alerting if the score s >= t."""
    y = np.asarray(y, bool); a = np.asarray(s) >= t
    return dict(vp=int(np.sum(a & y)), fp=int(np.sum(a & ~y)), fn=int(np.sum(~a & y)), vn=int(np.sum(~a & ~y)))

def metricas(vp, fp, fn, vn, beta=1.0):
    n = vp + fp + fn + vn; prec = vp / (vp + fp) if vp + fp else 0.0; rec = vp / (vp + fn) if vp + fn else 0.0
    esp = vn / (vn + fp) if vn + fp else 0.0
    fb = (1 + beta**2) * prec * rec / (beta**2 * prec + rec) if prec + rec else 0.0
    den = np.sqrt(float((vp + fp) * (vp + fn) * (vn + fp) * (vn + fn)))
    mcc = (vp * vn - fp * fn) / den if den else 0.0
    return dict(acierto=(vp + vn) / n, precision=prec, exhaustividad=rec, especificidad=esp,
                f=fb, acierto_equilibrado=(rec + esp) / 2, mcc=mcc)

def _ordenar(y, s):
    o = np.argsort(-np.asarray(s, float), kind="mergesort"); y = np.asarray(y, bool)[o]; s = np.asarray(s, float)[o]
    corte = np.r_[np.where(np.diff(s))[0], len(s) - 1]          # last index of each distinct value
    return np.cumsum(y)[corte], np.cumsum(~y)[corte], s[corte]

def curva_roc(y, s):
    vp, fp, umb = _ordenar(y, s)
    return np.r_[0, fp / fp[-1]], np.r_[0, vp / vp[-1]], np.r_[np.inf, umb]

def area(x, y):
    return float(np.sum(np.diff(x) * (y[1:] + y[:-1]) / 2))

def curva_pr(y, s):
    vp, fp, umb = _ordenar(y, s)
    return vp / (vp + fp), vp / vp[-1], umb

def precision_media(y, s):
    """AP = sum of (R_n - R_{n-1}) * P_n: no interpolation, like scikit-learn."""
    p, r, _ = curva_pr(y, s); return float(np.sum(np.diff(np.r_[0, r]) * p))

def umbral_coste(c_fp, c_fn):
    """With calibrated probabilities, alert if p > c_fp / (c_fp + c_fn)."""
    return c_fp / (c_fp + c_fn)

def corregir_prior(p, factor):
    """If training multiplied the weight (or frequency) of the positives by 'factor',
    the probabilities come out inflated: divide the odds by 'factor'."""
    p = np.asarray(p, float); o = p / (1 - p) / factor; return o / (1 + o)

def smote(X, y, k=5, n_nuevos=None, seed=0):
    """Create synthetic positives on the segment between a positive and one of its k positive neighbors."""
    rng = np.random.default_rng(seed); X = np.asarray(X, float); y = np.asarray(y, bool); P = X[y]
    n_nuevos = (len(y) - 2 * len(P)) if n_nuevos is None else n_nuevos
    D = ((P[:, None, :] - P[None, :, :]) ** 2).sum(-1); np.fill_diagonal(D, np.inf); vec = np.argsort(D, 1)[:, :k]
    i = rng.integers(0, len(P), n_nuevos); j = vec[i, rng.integers(0, k, n_nuevos)]; u = rng.random((n_nuevos, 1))
    nuevos = P[i] + u * (P[j] - P[i])
    return np.vstack([X, nuevos]), np.r_[y, np.ones(n_nuevos, bool)]

def brier(y, p):
    return float(np.mean((np.asarray(p) - np.asarray(y, float)) ** 2))

d = semanas(); X = d.drop(columns="averia").values; y = d.averia.values

sc = StandardScaler().fit(Xtr); Xtr, Xte = sc.transform(Xtr), sc.transform(Xte)
pi = ytr.mean(); w = (1 - pi) / pi                                       # 42.29
for cw in (None, "balanced"):

§9 · Checklist

Before deploying a rare-event classifier

  • Prevalence measured and compared against the constant classifier.
  • Stratified splits; enough positives in validation and test.
  • PR curve and AP as the main ranking metric; ROC only as a complement.
  • FP and FN costs agreed with the business (or operational capacity) and threshold chosen on validation.
  • Probabilities calibrated (or prior-corrected if you rebalanced) before applying .
  • Resampling, if used, inside the pipeline and only on training data.
  • Confidence intervals for recall, precision and cost.
  • Production monitoring of prevalence and alert volume: if they change, recalibrate the threshold.

§10 · Worked example

A thousand trucks, 23 breakdowns and a 5% threshold

Confusion matrix, seven metrics, cost, Bayes threshold, Wilson interval and prior correction, by hand.

The setup. The maintenance shop manager wants to know whether the breakdown model is worth it. The vendor says it's "91% accurate". The model that never raises an alert is 97.7% accurate. Is it worse than doing nothing?

  1. The confusion matrix

    In words

    We cross what happened (breakdown or not) with what the model said (alert or not). That gives four cells that sum it all up.

    The data (alert threshold: 5%)

    alertno alerttotal
    broke downTP = 13FN = 1023
    didn't break downFP = 78TN = 899977
    total919091,000

    Where do these numbers come from?

    They are the 1,000 trucks from the simple version's toy with the threshold at 5%: the logistic regression model trained on the simulated fleet data. TP, FP, FN and TN are true positives, false positives, false negatives and true negatives.

  2. Accuracy, precision, recall and specificity

    The math

    What it means: accuracy (91.2%) is worse than never alerting (977/1000 = 97.7%), even though the model finds 13 breakdowns. Precision says 1 in 7 inspections finds something; recall, that a bit over half the breakdowns are prevented.

  3. F1, balanced accuracy and MCC

    In words

    Three ways to summarize the matrix in a single number that isn't fooled by the common class.

    The math

    Which one to use?

    F1 is the harmonic mean of precision and recall: it ignores TN, so the common class doesn't inflate it. Balanced accuracy is the average of each class's recall. MCC (Matthews correlation coefficient) is the correlation between actual and predicted, between −1 and 1, and uses all four cells. The never-alert model has F1 = 0, balanced accuracy = 0.5 and MCC = 0. None of them replaces putting a price on mistakes.

  4. The cost and the optimal threshold

    The math (breakdown that slips through: $4,000; unnecessary inspection: $150)

    Where does the threshold come from?

    For a truck with risk (well calibrated), alerting costs (the inspection, if it was healthy; the breakdown is prevented) and not alerting costs . Alerting pays off when , that is, when . It's the same decision rule as in the Bayes topic.

    What it means: the model saves 44% compared with doing nothing. The theoretical threshold (3.6%) is close to the 5% used; on the 10,000 test trucks, the empirical minimum is at 4.4%.

  5. How much can you trust recall?

    In words

    There are only 23 breakdowns, so each one moves recall by more than 4 points. We compute a Wilson confidence interval for the proportion 13/23.

    The math (z = 1.96, n = 23, p = 0.565)

    What it means: with 1,000 trucks, the model's true recall could be anywhere between 37% and 74%. To compare two models or fine-tune a threshold you need many more breakdowns in the test set: the 10,000 trucks of the technical version (230 breakdowns) or stratified cross-validation.

  6. Correcting a risk inflated by the weights

    In words

    A model trained with balanced weights gives a truck a 40% risk. The weights made each breakdown count as healthy trucks, so the model has learned odds in favor of a breakdown that are 42.5 times higher than the real ones. We divide them.

    The math

    What it means: the "40%" is really 1.5%, below the optimal threshold of 3.6%: with the correction, this truck isn't sent to inspection. Without it, it would have been. Using uncorrected risks with a cost threshold floods the maintenance shop.

print(10 * 4000 + 78 * 150, 23 * 4000, round(umbral_coste(150, 4000), 4))   # 51700 92000 0.0361

z, n, p = 1.96, 23, 13 / 23
c = (p + z**2 / (2 * n)) / (1 + z**2 / n); h = z * np.sqrt(p * (1 - p) / n + z**2 / (4 * n**2)) / (1 + z**2 / n)
print(round(c - h, 3), round(c + h, 3))                                       # 0.368 0.744

What would change in a real system

  • More weeks in the test set, so the recall interval is useful.
  • Costs per breakdown type (a brake failure doesn't cost the same as a lighting failure) and, if needed, one model per type.
  • Maintenance shop capacity as a constraint: if only 60 inspections fit per week, that queue sets the threshold.
  • Monitored prevalence: in winter breakdowns go up and the same threshold produces more alerts.
