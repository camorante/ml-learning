Split before you look, for programmers

What exactly a test set estimates and with how much noise, how to choose between random, time-based and group splits, the taxonomy of data leakage and how to detect it, and why all preprocessing must live inside a Pipeline. With the splits implemented from scratch (indices identical to scikit-learn), a comparison on fleet data and a worked example by hand.

Summary

  • The test error only estimates the production error if the test cases are obtained the way production cases will be obtained and are independent of the training data.
  • Time-ordered data: split by date, with a gap (purge) equal to the longest window used by the features. Data with repeated entities (trucks, drivers) that will show up new: group split.
  • Leakage = information that won't exist at prediction time. Three sources: columns from the future, dependence between rows, and preprocessing fitted on all the data.
  • Everything that is "learned" from the data (means, scales, chosen columns, thresholds) is fitted inside each validation fold. A Pipeline guarantees it.

§1 · What is being estimated

Generalization error and its noise

What we care about is the risk of the trained model, its expected loss over the production distribution . The average error on a test set is an unbiased estimator of that risk if two conditions hold:

  • the test cases are samples from (same period, same truck types, same prediction horizon);
  • they are independent of the training data and have not been used to make any decision.

Even when they hold, the estimate has variance. For an accuracy measured with independent cases, the standard error is

With and , : the 95% interval spans about ±6 points. For a continuous loss like MAE, with the standard deviation of the errors. For proportions with small or close to 0 or 1, the Wilson interval is better.

Watch out for independence. If the test set has 60 trucks × 70 days, that's not 4,200 independent cases: errors from the same truck are correlated (its own bias repeats every day). The honest standard error is computed with the variance between trucks. In the simulated fleet (§8), the naive interval is [2.54, 2.66] and the one clustered by truck is [2.30, 2.90]: five times wider.

§2 · Schemes

Three sets, cross-validation and nested validation

Every time a set is used to decide (which model, which hyperparameters, which threshold), its error stops being an unbiased estimate: you pick the best of several noisy results, and the best tends to be optimistic. That's why three roles are kept apart:

  • Training: fits the model's parameters.
  • Validation: chooses hyperparameters and compares models. It gets "worn out" with use.
  • Test: looked at once, at the end, to give the figure.

With little data, validation is replaced by k-fold cross-validation: the development set is cut into folds, the model is trained times leaving one out, and the errors are averaged. The mean has less variance than a single split, but the errors are not independent (the training runs share almost all their data), so their standard deviation across folds underestimates the real uncertainty.

For classification with imbalanced classes, the stratified variant keeps each class's proportion in every fold. If you also search for hyperparameters, the honest estimate of the whole procedure is nested validation: an outer loop gives the grade and, inside each fold, an inner loop chooses the hyperparameters using only that fold's training data.

The random split (k-fold with shuffle=True) is only valid if the rows are exchangeable: none carries information about another. In telemetry they almost never are: there's time order and there are repeated entities. The next two sections deal with each case. The widget lets you compare the schemes.

§3 · Time order

When there's time: train on the past, test on the future

If the target has autocorrelation (today's fuel use resembles yesterday's), a random split puts into the test set days whose neighbors are in the training set. The model doesn't have to extrapolate, only interpolate, and the error comes out optimistic. This happens even with no date column at all: it's enough for some feature to identify the moment (in the fleet, the odometer gives away the exact day).

TimeSeriesSplit implements rolling-origin validation: fold trains on everything before an instant and tests on the next block. It mimics exactly a system that is retrained periodically.

Two important adjustments:

  • Gap or purge (gap): if a feature uses a window of days (average of the last 7 days), or the label looks days ahead ("breakdown in the next 14 days?"), the rows just before the test set share information with it. Remove days from training.
  • Embargo: if you also train on data after the test set (blocked k-fold, useful when history is short), also remove a few days right after the test block.

With many trucks per day, the split is done by unique dates, not by rows: otherwise a single day can end up split between training and test, and the rest of the fleet that day "tells on" the conditions (temperature, traffic). The date_split function in §7 does this.

§4 · Repeated entities

When there are groups: whole trucks on one side

Each truck has its own bias (engine, body, driver). If its days are spread across training and test, the model can learn to recognize the truck and apply its bias. That works on the test set, but it's useless for trucks it hasn't seen. The rule:

  • if production will only have known trucks, the group split is pessimistic and the time-based split is enough;
  • if new trucks (or customers, or fleets) will arrive, the test set must have groups that aren't in training: GroupKFold, GroupShuffleSplit or StratifiedGroupKFold;
  • if both, combine them: new groups and later dates.

GroupKFold assigns groups deterministically: it sorts the groups from most to fewest rows and assigns each one to the fold with the fewest rows so far (a greedy heuristic to balance sizes). With shuffle=True (scikit-learn ≥ 1.6) it shuffles them and cuts them into folds with an equal number of groups.

A hint that the model is recognizing entities: a feature with very high importance that has no causal relationship with the target. In the simulated fleet, the odometer: without it, the error on new trucks drops from 2.43 to 2.22 L.

Warning signs. A result much better than any simple baseline; a single feature with enormous importance; a validation error that doesn't change when almost all features are removed; a model that gets much worse when it goes to production.

Adversarial validation. To check that the test set resembles production (or that training resembles the test set), label each row by its set and train a classifier to tell them apart. An AUC close to 0.5 means they can't be told apart. A high AUC signals a distribution shift, and that classifier's most important features say which one. In the simulated fleet it gives 0.94: the temperature reveals that production is winter (5.7 °C on average versus 15.9 °C) and the odometer, that it comes later. That's not leakage, it's drift, and it warns that the production error may differ from the validation error (topic 8).

§6 · Preprocessing

Everything that learns goes inside the Pipeline

Imputing with the mean, scaling, selecting the best columns or encoding a category with the target mean are estimators: they have a fit that looks at the data. If they're fitted before splitting, the test set has influenced the model. The extreme case: 100 rows with 2,000 noise columns and a random label. Selecting the 20 most correlated columns using all the data, cross-validation gives 85% accuracy; selecting them inside each fold, 50%, which is the truth.

With a Pipeline, cross_val_score calls fit on every step using only each fold's training rows, and transform on the test rows. ColumnTransformer does the same by column (numeric scaled, categorical encoded).

seleccion_con_fuga.py · actual output in the comments (scikit-learn 1.9)

import numpy as np
from sklearn.linear_model import LogisticRegression
from sklearn.feature_selection import SelectKBest, f_classif
from sklearn.model_selection import StratifiedKFold, cross_val_score
from sklearn.pipeline import make_pipeline

fuera, dentro = [], []
for s in range(40):                                        # 40 experiments with pure noise
    r = np.random.default_rng(100 + s)
    X, y = r.normal(size=(100, 2000)), r.integers(0, 2, 100)
    cv = StratifiedKFold(5, shuffle=True, random_state=s)
    X20 = SelectKBest(f_classif, k=20).fit_transform(X, y)  # WRONG: selects looking at the test too
    fuera.append(cross_val_score(LogisticRegression(max_iter=2000), X20, y, cv=cv).mean())
    pipe = make_pipeline(SelectKBest(f_classif, k=20), LogisticRegression(max_iter=2000))
    dentro.append(cross_val_score(pipe, X, y, cv=cv).mean())  # RIGHT: selects in each fold
print(f"outside {np.mean(fuera):.3f}   inside {np.mean(dentro):.3f}")
# outside 0.847   inside 0.495

§7 · From scratch

The splits, implemented and verified

Each function returns pairs of indices. kfold, time_series_split and group_kfold produce exactly the same indices as their scikit-learn equivalents across 900 random configurations. date_split and blocked_kfold_purged have no direct equivalent; their properties are checked (no training date within gap days of the test set). mae_interval gives the MAE interval, optionally clustered.

splits.py

import numpy as np

def kfold(n, k=5, shuffle=False, seed=None):
    idx = np.arange(n)
    if shuffle:
        np.random.RandomState(seed).shuffle(idx)      # same generator as sklearn
    sizes = np.full(k, n // k); sizes[: n % k] += 1    # the first n % k folds get one extra
    start = 0
    for s in sizes:
        test = idx[start:start + s]
        yield np.setdiff1d(idx, test), np.sort(test)  # sklearn returns both sorted
        start += s

def time_series_split(n, k=5, test_size=None, gap=0):
    """Rolling origin: train on the past, test on the next block."""
    test_size = test_size or n // (k + 1)
    for start in range(n - k * test_size, n, test_size):
        yield np.arange(0, start - gap), np.arange(start, start + test_size)

def group_kfold(groups, k=5):
    """Each whole group to one fold; the big ones first, to the lightest fold."""
    uniq, gidx = np.unique(groups, return_inverse=True)
    size = np.bincount(gidx)
    order = np.argsort(size, kind="stable")[::-1]
    load = np.zeros(k); fold_of = np.zeros(len(uniq), int)
    for g in order:
        f = np.argmin(load); load[f] += size[g]; fold_of[g] = f
    fold = fold_of[gidx]
    for f in range(k):
        yield np.where(fold != f)[0], np.where(fold == f)[0]

def date_split(dates, k=5, gap=0):
    """Many trucks per day: rolling origin over the unique dates, purging 'gap' days."""
    d = np.asarray(dates); u = np.unique(d)
    for tr_d, te_d in time_series_split(len(u), k, gap=gap):
        yield np.where(np.isin(d, u[tr_d]))[0], np.where(np.isin(d, u[te_d]))[0]

def blocked_kfold_purged(dates, k=5, gap=0):
    """k-fold over blocks of contiguous dates, purging 'gap' days on each side of the test."""
    d = np.asarray(dates); u = np.unique(d); pos = np.arange(len(u))
    for _, te in kfold(len(u), k):
        keep = (pos < te.min() - gap) | (pos > te.max() + gap)
        yield np.where(np.isin(d, u[keep]))[0], np.where(np.isin(d, u[te]))[0]

def mae_interval(err_abs, z=1.96, bloques=None):
    """Normal CI of the MAE. With 'bloques' (truck, week) it uses the between-block variance."""
    e = np.asarray(err_abs, float); m = e.mean()
    if bloques is None:
        se = e.std(ddof=1) / np.sqrt(len(e))
    else:
        b = np.asarray(bloques); ub = np.unique(b)
        mb = np.array([e[b == x].mean() for x in ub]); w = np.array([(b == x).sum() for x in ub])
        se = np.sqrt(np.sum(w**2 * (mb - m)**2) / np.sum(w)**2 * len(ub) / (len(ub) - 1))
    return m - z * se, m + z * se

The clustered standard error in mae_interval is the ratio estimator for a cluster mean: it treats each block as one observation weighted by its number of rows. It's the right version when the rows of a block share error, and it tends to the naive one if the blocks are independent inside.

§8 · In the fleet

Three cross-validations versus reality

Simulated data for 60 trucks over 400 days (fuel use with a per-truck effect, slow drift in condition and seasonality). Development uses the first 330 days and "reality" is the next 70, with the model retrained on the whole development set.

flota_cv.py · actual output in the comments

import numpy as np
from sklearn.ensemble import HistGradientBoostingRegressor, HistGradientBoostingClassifier
from sklearn.model_selection import KFold, GroupKFold, cross_val_score, cross_val_predict
from sklearn.metrics import roc_auc_score
from sim import flota                       # fleet simulator (included in the download)
from splits import date_split, mae_interval

df = flota(); X_COLS = ["km", "carga", "ralenti", "pendiente", "temp", "odometro"]
dev, prod = df[df.dia < 330].reset_index(drop=True), df[df.dia >= 330].reset_index(drop=True)
X, y = dev[X_COLS], dev.consumo
modelo = HistGradientBoostingRegressor(max_iter=300, random_state=0)

esquemas = {
    "KFold mezclado": KFold(5, shuffle=True, random_state=0).split(X),
    "GroupKFold (camión)": GroupKFold(5).split(X, groups=dev.camion),
    "por fecha, hueco 7 d": date_split(dev.dia, k=5, gap=7),
}
for nombre, cv in esquemas.items():
    s = -cross_val_score(modelo, X, y, cv=list(cv), scoring="neg_mean_absolute_error")
    print(f"{nombre:22s} MAE {s.mean():.2f} ± {s.std():.2f}")
# KFold mezclado         MAE 2.16 ± 0.03
# GroupKFold (camión)    MAE 2.48 ± 0.19
# por fecha, hueco 7 d   MAE 2.52 ± 0.14
# (keys: shuffled KFold · GroupKFold by truck · by date with a 7-day gap)

err = np.abs(prod.consumo - modelo.fit(X, y).predict(prod[X_COLS]))
(lo, hi), (lo2, hi2) = mae_interval(err), mae_interval(err, bloques=prod.camion)
print(f"production MAE {err.mean():.2f}   naive [{lo:.2f}, {hi:.2f}]   by truck [{lo2:.2f}, {hi2:.2f}]")
# production MAE 2.60   naive [2.54, 2.66]   by truck [2.30, 2.90]

# adversarial validation: can development be told apart from production?
etiqueta = np.r_[np.zeros(len(dev)), np.ones(len(prod))]
A = np.vstack([dev[X_COLS], prod[X_COLS]])
p = cross_val_predict(HistGradientBoostingClassifier(random_state=0), A, etiqueta,
                      cv=KFold(5, shuffle=True, random_state=0), method="predict_proba")[:, 1]
print(f"adversarial AUC {roc_auc_score(etiqueta, p):.3f}")
# adversarial AUC 0.944   (without the odometer: 0.875)

Shuffled KFold promises 2.16 L with a deceptively small spread across folds (±0.03). The two validations that respect the structure (by truck and by date) give 2.48–2.52 L, close to the real 2.60; the remaining difference is the seasonal drift that adversarial validation detects. In the simple version, the "tomorrow's liters" feature takes the test to 0.81 L and production to 5.41 L: no split can save a column from the future.

§9 · Checklist

Before giving an error figure

  • Written down how the model will be used: prediction moment, horizon, retraining frequency, new entities?
  • Test set set aside before exploring, with the scheme that imitates that use (date, group or both).
  • Duplicates removed before splitting.
  • Each column stamped with the instant it becomes known; windows that end at .
  • Gap between training and test ≥ the longest window and the label horizon.
  • All preprocessing inside a Pipeline; hyperparameters with nested validation or a separate set.
  • Confidence interval computed with the right independent unit (truck, week).
  • Comparison with a simple baseline (persistence, the truck's mean) and adversarial validation against the most recent data.

§10 · Worked example

The same model, two different grades

Ten months of fuel use for one truck, a nearest-neighbors-in-time model and two ways of setting aside the test set. All the math is done by hand and then checked with Python.

The setup. We want a model that predicts a truck's average fuel use over the coming months. We have 10 months of history. Before putting it into service, we have to give the fleet manager an error figure.

Example map

With the 10 months we have, we test the same model in two ways: setting aside three random months and setting aside the last three. Then three real months arrive and we see which of the two grades was right. We finish by measuring how much we can trust a grade computed from only three cases.

  1. The data and the model.
  2. Test with random months.
  3. Test with the last months.
  4. What actually happened.
  5. Why: the distance to the nearest data point.
  6. How much to trust a grade from three cases?

  1. The data and the model

    In words

    Monthly average fuel use of one truck, which rises slowly because of wear. The model is as simple as it gets: to predict a month, it averages the two training months closest on the calendar (on a tie, the earlier one wins). It's a nearest neighbor in time, like the k-NN of the ML series with k = 2.

    The data

    Month12345
    L/100 km3031313233
    Month678910
    L/100 km3334353536

    Where do these numbers come from?

    They're made up so the math works out by hand, but they mimic what you see in the fleet: a slow rise (about 0.6 L per month) with small ups and downs. What matters is that each month's value is very similar to its neighbors'. That's what makes the random split dangerous.

  2. Test with random months

    In words

    We set aside months 3, 6 and 9 (30%, as train_test_split would). The model trains on the other seven. For each test month it looks for its two training neighbors: one right before and one right after.

    The math

    Why those neighbors?

    For month 3, the closest training months are 2 and 4 (one month away). For 6, months 5 and 7. For 9, months 8 and 10. The model is interpolating: it fills a gap between two known values.

  3. Test with the last months

    In words

    Now we set aside months 8, 9 and 10, and train on months 1 to 7. For all three test months, the two nearest neighbors are always months 7 and 6, because there's nothing after them.

    The math

    What it means: the same model scores 0.5 or 1.83 depending on how the test set is set aside. Both calculations are correct; what changes is the question they answer. The first measures "fill in a missing month"; the second, "predict the coming months".

  4. What actually happened

    In words

    We retrain on all 10 months (as is done before putting the model into service), and months 11, 12 and 13 arrive with 37, 37 and 38 L. For all three, the nearest neighbors are months 10 and 9.

    The math

    What it means: the random split promised an error 3.7 times smaller than the real one (). The time-based one got it right. Here it matches to the decimal because the data is a toy; in the simulated fleet of the simple version, the time-based split gives 2.45 versus 2.60 in reality, and the random one 2.18.

  5. Why: the distance to the nearest data point

    In words

    A practical way to check whether a test set is realistic: for each test case, measure how far away its most similar training data point is (here, in months) and compare that with what will happen in production.

    The math

    SchemeDistance to the nearest neighbor
    Random (3, 6, 9)1, 1, 1 month
    Last months (8, 9, 10)1, 2, 3 months
    Production (11, 12, 13)1, 2, 3 months

    What if production retrains every month?

    Then production always predicts 1 month ahead, and a realistic test would be a repeated "one step ahead": train on 1–7 and test on 8, train on 1–8 and test on 9, and so on. That's TimeSeriesSplit(test_size=1). The rule doesn't change: the test imitates the real horizon and retraining frequency (§3).

  6. How much to trust a grade from three cases?

    In words

    With only three errors, the grade is very noisy. We compute its standard error: the standard deviation of the errors divided by the square root of the number of cases.

    The math

    Where do the 1.96 and the "3 − 1" come from?

    1.96 is the number of standard errors that keeps 95% of a normal distribution inside. We divide by instead of 3 because the mean was computed from the same data, and that makes the errors look somewhat more alike than they really are. With so few cases, the right thing is to use Student's t with 2 degrees of freedom (4.30 instead of 1.96): , that is, between 0.4 and 3.3 L. For a useful grade, you need many more cases or to repeat the split several times (§1 and §2).

    What it means: the time-based split gives the right grade, but with three test months we couldn't tell a 1.2 L model from a 2.5 L one. Both things matter: that the test set looks like production and that it's large enough.

ejemplo_meses.py · reproduces the numbers above

import numpy as np
mes = np.arange(1, 11); y = np.array([30, 31, 31, 32, 33, 33, 34, 35, 35, 36.])
futuro, y_fut = np.array([11, 12, 13]), np.array([37, 37, 38.])

def vecinos_en_el_tiempo(m_tr, y_tr, m):
    """Mean of the 2 closest training months (on a tie, the earlier one wins)."""
    orden = np.lexsort((m_tr, np.abs(m_tr - m)))
    return y_tr[orden[:2]].mean()

def evalua(test):
    tr = ~np.isin(mes, test)
    p = np.array([vecinos_en_el_tiempo(mes[tr], y[tr], m) for m in test])
    return p, np.abs(p - y[np.isin(mes, test)]).mean()

print(evalua(np.array([3, 6, 9])))      # [31.5 33.5 35.5] 0.5
print(evalua(np.array([8, 9, 10])))     # [33.5 33.5 33.5] 1.833
p = np.array([vecinos_en_el_tiempo(mes, y, m) for m in futuro])
print(p, np.abs(p - y_fut).mean())      # [35.5 35.5 35.5] 1.833

What would change in a real system

  • Many trucks: split by unique dates for the whole fleet and, if new trucks will arrive, by groups as well.
  • Several folds: rolling origin with 5–10 cutoffs instead of just one, to get more test cases and see whether the error changes with the season.
  • Baseline: always compare with "next month same as the last one" (persistence). If the model doesn't beat it, it adds nothing.
  • Interval clustered by truck, because its months are not independent.
