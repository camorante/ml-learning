Clases desbalanceadas, para programadores

Métricas de la matriz de confusión y cuáles resisten la prevalencia, curvas ROC y precisión-exhaustividad con sus líneas base, el umbral de Bayes a partir de costes, lo que hacen de verdad los pesos de clase y el remuestreo (SMOTE incluido), la corrección de probabilidades por cambio de prior y la calibración. Con un módulo desde cero idéntico a scikit-learn, 20 000 semanas-camión simuladas y un ejemplo resuelto a mano.

Resumen

  • Con prevalencia pequeña, el clasificador constante tiene acierto . Se evalúa con precisión, exhaustividad, curva PR y, sobre todo, con el coste esperado.
  • La curva ROC no depende de ; la PR sí, y su línea base es . Con clases raras, la PR describe mejor lo que ve el usuario de las alertas.
  • Pesos de clase y remuestreo apenas cambian el orden de las puntuaciones (AUC y AP iguales en la flota): sobre todo desplazan el umbral efectivo e inflan las probabilidades.
  • Si se reequilibra con factor , las probabilidades se corrigen dividiendo las odds entre . Sin corregir, el umbral de costes da un resultado peor que no avisar nunca.
  • Con pocos positivos, todas las métricas tienen mucha varianza: validación estratificada e intervalos de confianza.

§4 · Reequilibrar

Pesos de clase, remuestreo y SMOTE

Pesos: la pérdida se pondera, , con class_weight="balanced" = . Para la log-loss, multiplicar el peso de los positivos por equivale a multiplicar su frecuencia por : el modelo estima las odds de un mundo con prior tal que . En una logística bien especificada, eso es sumar al intercepto: el orden de las puntuaciones no cambia, solo el umbral efectivo.

Remuestreo: sobremuestrear positivos (copias) o submuestrear negativos tiene el mismo efecto en esperanza, con más varianza (las copias sobreajustan; el submuestreo tira información). SMOTE crea positivos sintéticos , , con uno de los vecinos positivos de : suaviza la región positiva, pero inventa puntos que pueden caer en zonas negativas y no aporta información nueva.

Regla de oro: todo remuestreo va dentro de la validación cruzada, solo sobre el pliegue de entrenamiento (imblearn.pipeline.Pipeline). Remuestrear antes de dividir mete copias de un mismo positivo en entrenamiento y prueba: fuga (tema 1).

§6 · Evaluación

Pocos positivos, mucha varianza

Con positivos en la prueba, la exhaustividad es una proporción binomial con error estándar : con 23 averías y , el intervalo de Wilson del 95 % va de 0,37 a 0,74. Recomendaciones:

  • Estratificar todas las divisiones (StratifiedKFold, stratify=y) para que cada pliegue tenga su parte de positivos; con grupos o tiempo, StratifiedGroupKFold o asegurar positivos en cada bloque temporal.
  • Agregar predicciones fuera de pliegue (cross_val_predict) y calcular una sola curva PR, en vez de promediar AP de pliegues con 5 positivos.
  • Intervalos por bootstrap estratificado para AP y coste.
  • Elegir el umbral en validación, no en la prueba, y reportar el coste en la prueba con ese umbral fijo.

§7 · Desde cero

Métricas, curvas y SMOTE verificados

imb.py

"""Métricas y técnicas para clases desbalanceadas, desde cero."""
import numpy as np

def matriz(y, s, t):
    """Verdaderos/falsos positivos y negativos al avisar cuando la puntuación s >= t."""
    y = np.asarray(y, bool); a = np.asarray(s) >= t
    return dict(vp=int(np.sum(a & y)), fp=int(np.sum(a & ~y)), fn=int(np.sum(~a & y)), vn=int(np.sum(~a & ~y)))

def metricas(vp, fp, fn, vn, beta=1.0):
    n = vp + fp + fn + vn; prec = vp / (vp + fp) if vp + fp else 0.0; rec = vp / (vp + fn) if vp + fn else 0.0
    esp = vn / (vn + fp) if vn + fp else 0.0
    fb = (1 + beta**2) * prec * rec / (beta**2 * prec + rec) if prec + rec else 0.0
    den = np.sqrt(float((vp + fp) * (vp + fn) * (vn + fp) * (vn + fn)))
    mcc = (vp * vn - fp * fn) / den if den else 0.0
    return dict(acierto=(vp + vn) / n, precision=prec, exhaustividad=rec, especificidad=esp,
                f=fb, acierto_equilibrado=(rec + esp) / 2, mcc=mcc)

def _ordenar(y, s):
    o = np.argsort(-np.asarray(s, float), kind="mergesort"); y = np.asarray(y, bool)[o]; s = np.asarray(s, float)[o]
    corte = np.r_[np.where(np.diff(s))[0], len(s) - 1]          # último índice de cada valor distinto
    return np.cumsum(y)[corte], np.cumsum(~y)[corte], s[corte]

def curva_roc(y, s):
    vp, fp, umb = _ordenar(y, s)
    return np.r_[0, fp / fp[-1]], np.r_[0, vp / vp[-1]], np.r_[np.inf, umb]

def area(x, y):
    return float(np.sum(np.diff(x) * (y[1:] + y[:-1]) / 2))

def curva_pr(y, s):
    vp, fp, umb = _ordenar(y, s)
    return vp / (vp + fp), vp / vp[-1], umb

def precision_media(y, s):
    """AP = suma de (R_n - R_{n-1}) * P_n: sin interpolar, como scikit-learn."""
    p, r, _ = curva_pr(y, s); return float(np.sum(np.diff(np.r_[0, r]) * p))

def umbral_coste(c_fp, c_fn):
    """Con probabilidades calibradas, avisar si p > c_fp / (c_fp + c_fn)."""
    return c_fp / (c_fp + c_fn)

def corregir_prior(p, factor):
    """Si el entrenamiento multiplicó el peso (o la frecuencia) de los positivos por 'factor',
    las probabilidades salen infladas: se divide la razón de apuestas entre 'factor'."""
    p = np.asarray(p, float); o = p / (1 - p) / factor; return o / (1 + o)

def smote(X, y, k=5, n_nuevos=None, seed=0):
    """Crea positivos sintéticos en el segmento entre un positivo y uno de sus k vecinos positivos."""
    rng = np.random.default_rng(seed); X = np.asarray(X, float); y = np.asarray(y, bool); P = X[y]
    n_nuevos = (len(y) - 2 * len(P)) if n_nuevos is None else n_nuevos
    D = ((P[:, None, :] - P[None, :, :]) ** 2).sum(-1); np.fill_diagonal(D, np.inf); vec = np.argsort(D, 1)[:, :k]
    i = rng.integers(0, len(P), n_nuevos); j = vec[i, rng.integers(0, k, n_nuevos)]; u = rng.random((n_nuevos, 1))
    nuevos = P[i] + u * (P[j] - P[i])
    return np.vstack([X, nuevos]), np.r_[y, np.ones(n_nuevos, bool)]

def brier(y, p):
    return float(np.mean((np.asarray(p) - np.asarray(y, float)) ** 2))

import numpy as np
from sim import semanas                  # simulador (incluido en la descarga)
from imb import matriz, curva_roc, area, precision_media, corregir_prior, brier, umbral_coste
from sklearn.linear_model import LogisticRegression
from sklearn.preprocessing import StandardScaler
from sklearn.model_selection import train_test_split

d = semanas(); X = d.drop(columns="averia").values; y = d.averia.values
Xtr, Xte, ytr, yte = train_test_split(X, y, test_size=0.5, stratify=y, random_state=0)
sc = StandardScaler().fit(Xtr); Xtr, Xte = sc.transform(Xtr), sc.transform(Xte)
pi = ytr.mean(); w = (1 - pi) / pi                                       # 42.29
for cw in (None, "balanced"):
    p = LogisticRegression(max_iter=3000, class_weight=cw).fit(Xtr, ytr).predict_proba(Xte)[:, 1]
    fx, ty, _ = curva_roc(yte, p)
    pc = p if cw is None else corregir_prior(p, w)
    print(cw, round(area(fx, ty), 4), round(precision_media(yte, p), 4), round(p.mean(), 4),
          round(brier(yte, p), 4), round(brier(yte, pc), 4))

§9 · Checklist

Antes de desplegar un clasificador de eventos raros

  • Prevalencia medida y comparada con el clasificador constante.
  • Divisiones estratificadas; positivos suficientes en validación y prueba.
  • Curva PR y AP como métrica principal de ordenación; ROC solo como complemento.
  • Costes de FP y FN acordados con negocio (o capacidad operativa) y umbral elegido en validación.
  • Probabilidades calibradas (o corregidas por el prior si se reequilibró) antes de aplicar .
  • Remuestreo, si se usa, dentro del pipeline y solo sobre entrenamiento.
  • Intervalos de confianza para exhaustividad, precisión y coste.
  • Seguimiento en producción de la prevalencia y del número de alertas: si cambian, recalibrar el umbral.

§10 · Ejemplo resuelto

Mil camiones, 23 averías y un límite del 5 %

Matriz de confusión, siete métricas, coste, umbral de Bayes, intervalo de Wilson y corrección de prior, a mano.

La situación. El jefe de taller quiere saber si el modelo de averías merece la pena. Su proveedor le dice que "acierta el 91 %". El modelo que no avisa nunca acierta el 97,7 %. ¿Es peor que no hacer nada?

Mapa del ejemplo

Mil camiones en una semana, 23 averías y un modelo que avisa cuando el riesgo pasa del 5 %. Calculamos a mano la matriz de confusión y todas las métricas, el coste frente a no avisar, el umbral óptimo por costes, cuánto ruido tiene la exhaustividad con solo 23 averías y cómo corregir el riesgo de un modelo entrenado con pesos.

  1. La matriz de confusión

    Cruzamos lo que pasó (avería o no) con lo que dijo el modelo (aviso o no). Salen cuatro casillas que lo resumen todo.

    Los datos (límite de aviso: 5 %)

    ¿De dónde salen estos números?

    Son los 1 000 camiones del juguete de la versión sencilla con el límite en el 5 %: el modelo de regresión logística entrenado con los datos de la flota simulada. VP, FP, FN y VN son verdaderos positivos, falsos positivos, falsos negativos y verdaderos negativos.

  2. Acierto, precisión, exhaustividad y especificidad

    La cuenta

    Qué significa: el acierto (91,2 %) es peor que el de no avisar nunca (977/1000 = 97,7 %), aunque el modelo encuentra 13 averías. La precisión dice que 1 de cada 7 revisiones encuentra algo; la exhaustividad, que se evita algo más de la mitad de las averías.

  3. F1, acierto equilibrado y MCC

    En palabras

    Tres formas de resumir la matriz en un solo número que no se deje engañar por la clase frecuente.

    La cuenta

    ¿Cuál usar?

    F1 es la media armónica de precisión y exhaustividad: ignora los VN, así que no la infla la clase frecuente. El acierto equilibrado es la media de la exhaustividad de cada clase. El MCC (coeficiente de Matthews) es la correlación entre lo real y lo predicho, entre −1 y 1, y usa las cuatro casillas. El modelo que nunca avisa tiene F1 = 0, acierto equilibrado = 0,5 y MCC = 0. Ninguno sustituye a poner precio a los errores.

  4. El coste y el umbral óptimo

    La cuenta (avería que se escapa: 4 000 €; revisión innecesaria: 150 €)

    ¿De dónde sale el umbral?

    Para un camión con riesgo (bien calibrado), avisar cuesta (la revisión, si estaba sano; la avería se evita) y no avisar cuesta . Avisar sale a cuenta cuando , es decir, cuando . Es la misma regla de decisión del tema de Bayes.

    Qué significa: el modelo ahorra un 44 % frente a no hacer nada. El umbral teórico (3,6 %) está cerca del 5 % usado; en los 10 000 camiones de prueba, el mínimo empírico está en el 4,4 %.

  5. ¿Cuánto fiarse de la exhaustividad?

    En palabras

    Solo hay 23 averías, así que cada una mueve la exhaustividad más de 4 puntos. Calculamos un intervalo de confianza de Wilson para la proporción 13/23.

    La cuenta (z = 1,96, n = 23, p = 0,565)

    Qué significa: con 1 000 camiones, la exhaustividad real del modelo podría estar entre el 37 % y el 74 %. Para comparar dos modelos o elegir un umbral fino hacen falta muchas más averías en la prueba: los 10 000 camiones de la versión técnica (230 averías) o validación cruzada estratificada.

  6. Corregir un riesgo inflado por los pesos

    En palabras

    Un modelo entrenado con pesos equilibrados da a un camión un riesgo del 40 %. Los pesos hicieron que cada avería contara como camiones sanos, así que el modelo ha aprendido unas apuestas a favor de avería 42,5 veces mayores que las reales. Las dividimos.

    La cuenta

    Qué significa: el "40 %" es en realidad un 1,5 %, por debajo del umbral óptimo del 3,6 %: con la corrección, este camión no se manda a revisión. Sin ella, se habría mandado. Usar riesgos sin corregir con un umbral de costes llena el taller.

Qué cambiaría en un sistema real

  • Más semanas en la prueba, para que el intervalo de la exhaustividad sea útil.
  • Costes por tipo de avería (una de frenos no cuesta lo mismo que una de luces) y, si hace falta, un modelo por tipo.
  • Capacidad del taller como restricción: si solo caben 60 revisiones por semana, el límite lo marca esa cola.
  • Prevalencia vigilada: en invierno las averías suben y el mismo límite da más alertas.
