Embeddings

Categories and words turned into vectors. A network can only do arithmetic with numbers, but much of a fleet's data are names: the truck, the route, the driver, the fault code. An embedding gives each name a few numbers that the network learns on its own while it solves another task. And in the end something curious happens: names that are alike end up with similar numbers, even though nobody told the network how they are alike.

The setup

When a truck comes into the maintenance shop, the diagnostic reader stores the fault codes it had on. Each code is a short label: “P0217” is engine overheating; “C0035”, a wheel sensor. The fleet in the example has 20 codes, from four systems: engine, exhaust, brakes and electrical. A breakdown usually turns on several codes from the same system at once. This is how the first visits begin:

The network does not know which system each code belongs to: to it, each code is just a number from 0 to 19. We give it a game: we show it one code from a visit and it has to guess which other code is in that same visit. To play, each code has 2 numbers, its embedding, which start out random and get adjusted along the way. With 2 numbers, each code is a point on a plane: the chart.

The network is trained on 400 visits (2,188 pairs of codes) and we check it on another 1,000 it has not seen. The snapshots in the chart come from that training, done for real.

What you just saw

A few numbers per category, learned

An embedding is a short list of numbers that stands for a category: here 2 per code, in practice anywhere from 2 to a few hundred. At first they are random numbers. The network adjusts them just like it adjusts its weights, little by little, to do better at its task.

The interesting part is the side effect: to guess a code's companions, it pays for the network to give similar numbers to codes that show up with the same companions. That is why codes from the same system end up pointing in the same direction. And “same direction” is measured with the cosine: 1 if two arrows point the same way, 0 if they are at a right angle, −1 if they point opposite ways.

The ideas that follow: why one-hot is not enough (1), what an embedding is on the inside (2), how it is learned (3), that directions mean something too (4), how many numbers to use (5) and how to look at embeddings with many numbers (6).

Idea 1 of 6

One-hot: many columns and all equally far apart

The most direct way to turn a category into numbers is one-hot, which already came up in preparing features: one column per category, with a 1 in its own and 0 in all the others. With 20 codes, 20 columns. It works, but it has two problems.

The first is size: a fleet with 5,000 routes needs 5,000 columns, almost all of them zero. The second is that one-hot says all categories are equally different: the distance between any two codes is always the same.

Idea 2 of 6

On the inside: a row of a table

The embeddings of the 20 codes are stored in a table with 20 rows and 2 columns. To give the network a code's embedding, you just take its row: there is nothing to compute.

And here is the link with one-hot: if you multiply a code's one-hot by the table, as with matrices, each row gets multiplied by its box of the one-hot. The 19 rows multiplied by 0 disappear and only the one with the 1 is left. So an embedding is an ordinary layer like the ones in topic 3, with the table as its weights, where we skip the multiplications by zero.

How to read the chart. Each row is a code. On the left, its box of the one-hot (0 or 1). In the middle, its row of the table: the 2 numbers it has learned. On the right, the row multiplied by its box. At the bottom, the sum of all of them: the embedding of the chosen code, in orange. Tap a row to choose another code.

Idea 3 of 6

How it is learned: only the row that was used moves

To play the companion-guessing game, the network also has an answer vector for each code. A code's score as a companion is the dot product of the seen code's embedding with that vector, and the scores are turned into probabilities with the softmax from topic 4. If the network misses, the backpropagation from topic 5 nudges the numbers so it does better next time.

What is special about an embedding is that in each step only the row of the code that was used changes: the others took no part and get no nudge. Idea 4 of 6

Directions mean something too

Another fleet splits its trips into 8 kinds of segment: 4 zones (downtown, industrial, road and highway), each one by day or by night. The network sees only the segment number and learns a 2-number embedding by predicting two things about each trip: fuel consumption (L/100 km) and idling minutes per hour. At night there is less traffic and less fuel is burned, but trucks wait longer at the loading docks with the engine running.

Nobody told the network what “night” is. Even so, going from day to night is almost the same arrow in all four zones: one direction of the plane means “night”.

Idea 5 of 6

How many numbers per category?

You decide the size of the embedding. With very few numbers, the differences don't fit; with too many, the network has more numbers to adjust with the same data and starts memorizing the quirks of the 400 visits. To choose, you try. Idea 6 of 6

Looking at 16 numbers: projecting and finding groups

A 2-number embedding can be drawn as it is. A 16-number one cannot: each code is a point in 16 dimensions. To see it you have to project it onto a plane, and the projection that loses the least is PCA: it looks for the two directions in which the points are most spread out. You can also look for groups directly in the 16 numbers, with k-means, without drawing anything.

Putting it all together

How an embedding is used

  1. Number the categories: each code, route or truck gets a row number. Keep one row for “unknown”: the new code the manufacturer releases tomorrow will go there.
  2. Create the table: one row per category and as many numbers as you like (2 here; in practice, from 4 to a few hundred), at random.
  3. Pick a task that needs to understand the categories: guessing the companion code, a segment's fuel consumption or a route's delay.
  4. Train: in each step, the network takes the rows it needs and backpropagation adjusts them along with the rest of the weights (topics 5 and 6).
  5. Use the numbers: as input to other models, to find similar categories by cosine or to find groups.

In the real world

Where it shows up in fleet telemetry

Fault codes

With thousands of codes from several manufacturers, the embedding groups the ones that show up together. A new or rare code is understood through its neighbors, and a network that predicts the next breakdown starts from those numbers instead of thousands of columns of zeros.

Routes, depots and drivers

To predict a trip's delay or fuel consumption, each route, depot, truck model and driver has its own embedding. Routes with the same kind of traffic end up close together, and the network learns from all of them at once.

Shop notes

“Noise in front wheel”, “leaking oil”: words are categories too. With word embeddings, a network reads the mechanics' notes and the drivers' messages. Language models start the same way: each piece of a word is a row of a huge table.

Similar trucks

With one embedding per truck, learned from its trips, you can find the most similar trucks by cosine: they are useful for comparing fuel consumption with peers or for estimating it for a newly arrived truck. The same numbers are reused in other models.

To be fair

What it gives you and what to watch out for

What it gives you

  • Few numbers per category: the toy network learns 100 numbers; with one-hot, 420. With thousands of categories, the difference is huge.
  • Similar categories end up close together, and the cosine measures how close.
  • The network learns it on its own, as a side effect of its task, without labeling anything by hand.
  • The numbers can be reused: in other models, to find similar items or to group them.

What to watch out for

  • A category that was not there during training has no row: you need to keep an “unknown” row.
  • Rare categories show up little and their numbers end up poorly fitted.
  • The numbers only reflect the task: if the task does not need a difference, the embedding does not learn it.
  • With too many numbers and little data, the neighbors get noisy: with 16 numbers, 55 of 60 neighbors are from the same system; with 2, all 60.

Mini glossary

The jargon, in plain English

Category
A value that is a name and not an amount: a fault code, a route, a truck.
One-hot
One column per category, with a 1 in its own and 0 in the others.
Embedding
A short list of numbers that stands for a category and that the network learns.
Embedding table
All those lists together, one row per category.
Dimension
How many numbers each embedding has.
Cosine
How alike the directions of two arrows are: 1 the same, 0 at a right angle, −1 opposite.
Neighbors
The categories with the highest cosine with a given one.
“Unknown” row
A row kept for the categories that were not seen during training.
Token
The piece of a word that a language model turns into an embedding.
Projection
Turning many numbers into two so you can draw them, losing something along the way.
