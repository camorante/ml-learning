PCA, for programmers

Principal component analysis: maximum variance and minimum reconstruction error are the same problem, it is solved with the eigenvectors of the covariance or, better, with the SVD of the centered data, and Eckart-Young says there is no better linear approximation. §5 · Decisions

Scale and number of components

Covariance or correlation. PCA on raw data maximizes variance in the original units: the feature with the largest range takes over component 1. Standardizing (PCA on the correlation matrix) gives each feature variance 1 and an equal "vote". Work on raw data only when all features share a unit and a meaningful scale (pixels, spectra, hourly profiles).

Choosing :

  • Cumulative variance target (90–99%): PCA(n_components=0.95).
  • Elbow of the scree plot: where the eigenvalues stop dropping.
  • Kaiser (on correlation): , that is, components that explain more than one original feature. It tends to overestimate.
  • Cross-validation of the final task: if PCA is a preprocessing step, is just another hyperparameter of the pipeline.

§6 · Limits

What PCA doesn't do

  • It ignores the target variable. The direction of greatest variance may have nothing to do with what you want to predict. Principal component regression (PCR) can throw away exactly the useful component; PLS looks for directions with maximum covariance with .
  • Linear. Curved manifolds → kernel PCA, Isomap; for visualization, t-SNE or UMAP (which don't preserve global distances and can't reconstruct).
  • Sensitive to extreme values: one faraway point drags component 1. Robust PCA (low-rank + sparse decomposition) or robust covariance estimators.
  • Components ≠ causes. They are combinations that summarize correlations; for interpretable factors use rotations (varimax) or factor analysis, ICA if you are looking for independent sources, NMF if everything is non-negative.
  • Whitening (whiten=True): divides each score by so they all have variance 1; useful before scale-sensitive algorithms, but it amplifies the noise of the small components.

§7 · Implementation

PCA from scratch

mypca.py · verified on load_digits (64 features): components equal to sklearn.decomposition.PCA within 8·10⁻¹⁵ (k = 2, 10, 30), variances within 2·10⁻¹³, transform and inverse_transform within 3·10⁻¹³; pca_eig gives the same eigenvalues

import numpy as np

class PCA:
    def __init__(self, n_components):
        self.k = n_components

    def fit(self, X):
        self.mean_ = X.mean(0)
        Xc = X - self.mean_                                  # 1) center
        U, s, Vt = np.linalg.svd(Xc, full_matrices=False)    # 2) SVD: Xc = U·diag(s)·Vt
        signs = np.sign(Vt[np.arange(len(Vt)), np.abs(Vt).argmax(1)])
        Vt *= signs[:, None]                                 # fixed sign: largest loading of each row, positive
        var = s ** 2 / (len(X) - 1)                          # eigenvalues of the covariance
        self.components_ = Vt[:self.k]                       # principal directions (rows)
        self.explained_variance_ = var[:self.k]
        self.explained_variance_ratio_ = var[:self.k] / var.sum()
        return self

    def transform(self, X):                                  # coordinates on the new axes
        return (X - self.mean_) @ self.components_.T

    def inverse_transform(self, Z):                          # reconstruction with k components
        return Z @ self.components_ + self.mean_

def pca_eig(X, k):
    """Same answer the other way: eigenvectors of the covariance matrix."""
    C = np.cov(X, rowvar=False)
    lam, V = np.linalg.eigh(C)                               # ascending order
    order = np.argsort(lam)[::-1][:k]
    return lam[order], V[:, order].T

§8 · In production

With libraries

digits.py · actual output in the comments (scikit-learn 1.9)

import numpy as np
from sklearn.datasets import load_digits
from sklearn.model_selection import train_test_split, cross_val_score
from sklearn.pipeline import make_pipeline
from sklearn.preprocessing import StandardScaler
from sklearn.decomposition import PCA
from sklearn.neighbors import KNeighborsClassifier

X, y = load_digits(return_X_y=True)                    # 1,797 digits of 8×8 pixels = 64 features
pca = PCA(n_components=0.95).fit(X)                    # keep 95% of the variance
print(pca.n_components_, pca.explained_variance_ratio_[:3].round(3))
# 29 [0.149 0.136 0.118]

Z = pca.transform(X)                                   # 1,797 × 29 instead of 1,797 × 64
perdida = np.sum((pca.inverse_transform(Z) - X) ** 2) / np.sum((X - X.mean(0)) ** 2)
print(f"variance lost on reconstruction: {perdida:.3f}")
# variance lost on reconstruction: 0.045

for nombre, modelo in [("KNN on 64 pixels", KNeighborsClassifier(3)),
                       ("PCA(95%) + KNN", make_pipeline(PCA(0.95), KNeighborsClassifier(3)))]:
    acc = cross_val_score(modelo, X, y, cv=5).mean()
    print(f"{nombre:20s} accuracy {acc:.3f}")
# KNN on 64 pixels     accuracy 0.967
# PCA(95%) + KNN       accuracy 0.966

With less than half the features the classifier is just as accurate, and each distance costs half as much. The pixels share a scale, which is why we don't standardize here; with features in different units, make_pipeline(StandardScaler(), PCA(...), ...). And always inside the pipeline, so PCA is fit only on the training folds.

§9 · Checklist

Before you trust your components

  • Decide covariance or correlation (standardize?) and justify it by the units.
  • Fit PCA on training data only, inside a Pipeline.
  • Check for extreme values first: a single point can define component 1.
  • Choose k by cumulative variance and, if it is a preprocessing step, by cross-validation of the task.
  • Interpret with the loadings, not the sign; check stability with the bootstrap.
  • If the goal is to predict, make sure the discarded components weren't carrying the signal (compare with PLS or with the model without PCA).

Summarizing each truck in a single number

The setup. A fleet dashboard wants to rank trucks by "workload" with a single indicator, based on average daily km and liters. It also wants to know what is lost by summarizing.

Each truck has two numbers (km and liters per day) that go very much hand in hand. We want to describe it with a single number, losing as little as possible. PCA does it in three moves: put both features on the same scale, measure how much they go together, and find the direction in which the trucks spread apart the most.

  1. Standardize: same scale for km and liters.
  2. Measure how much they go together: the correlation.
  3. Find the two principal directions.
  4. How much information does each one keep?
  5. Compute each truck's "shadow".
  6. Reconstruct from a single number and see what is lost.

    Km go from 80 to 280 and liters from 34 to 94: if we mix them as they are, km would weigh more just for having bigger numbers (idea 4 of the simple version). So we turn each value into "how many standard deviations it is above or below the average".

trucks_pca.py · reproduces the numbers above

import numpy as np
from sklearn.decomposition import PCA

X = np.array([[80, 34], [160, 82], [240, 58], [240, 82], [280, 94]], float)   # km and liters per day
Z = (X - X.mean(0)) / X.std(0, ddof=1)                 # standardize (sample standard deviation)
pca = PCA(2).fit(Z)
print(pca.explained_variance_, pca.explained_variance_ratio_)   # [1.75 0.25] [0.875 0.125]
print(pca.components_.round(4))                                 # [[0.7071 0.7071] [0.7071 -0.7071]]
print(pca.transform(Z).round(3))                                # A -2.121 · B (0, -0.707) · C (0, 0.707) · D 0.707 · E 1.414

What would change in a real system

  • More features (engine hours, idling, stops, load): component 1 would still be "work", and others with their own meaning would appear (city versus highway).
  • Standardize with the whole fleet and store the means and deviations to apply the same indicator to new trucks.
  • Watch component 2: in this case it is the most useful one for operations (trucks that burn too much) even though it explains little variance.
  • Normalize by vehicle type first, so you don't compare a light truck with a tractor unit.
