k vecinos más cercanos para programadores

El estimador no paramétrico más simple: la predicción en un punto es un promedio local de las respuestas de sus k vecinos. Distancias y escalado, el equilibrio sesgo-varianza que controla k, la garantía de Cover y Hart, índices para buscar rápido y la maldición de la dimensión. Con un KNN vectorizado en NumPy idéntico a scikit-learn y un ejemplo resuelto a mano.

Resumen

  • No hay entrenamiento: se guardan los datos. Predecir cuesta por consulta con fuerza bruta.
  • La métrica es el modelo: sin escalar, la variable de mayor rango domina la distancia.
  • controla el equilibrio sesgo-varianza: la varianza de la estimación es ; el sesgo crece con el radio del vecindario. Se elige por validación cruzada (leave-one-out es gratis).
  • Con , el error de 1-NN es como mucho el doble del error de Bayes (Cover y Hart, 1967).
  • En dimensión alta las distancias se concentran y los vecindarios dejan de ser locales; los índices exactos (KD-tree) también se degradan y se usan búsquedas aproximadas (HNSW, FAISS).

§1 · El modelo

Promedios locales

Sea el conjunto de índices de los puntos de entrenamiento más cercanos a según una distancia . Para clasificación se estima la probabilidad de cada clase por la frecuencia entre los vecinos, y para regresión, la media:

Con pesos por distancia, cada vecino contribuye con (y el promedio se normaliza por ). Generalizando los pesos a un núcleo sobre todos los puntos se obtiene la regresión de Nadaraya-Watson: KNN es un suavizador con ancho de banda adaptativo (el radio hasta el k-ésimo vecino), estrecho donde hay muchos datos y ancho donde hay pocos.

La frontera de decisión de 1-NN es un diagrama de Voronoi: cada punto de entrenamiento manda en la celda de puntos más cercanos a él. Con las celdas se mezclan y la frontera se suaviza.

§4 · Coste

Buscar vecinos rápido

Fuerza bruta: para consultas, operaciones y de memoria. Vectorizado con la identidad , el grueso es un producto de matrices (BLAS), y elegir los menores de cada fila cuesta con argpartition en vez de ordenando.

Los índices exactos podan regiones usando la desigualdad triangular: si la distancia de la consulta a una caja ya supera la del k-ésimo vecino encontrado, la caja entera se descarta. En dimensión alta casi ninguna caja se puede descartar (§5), y por eso los sistemas de búsqueda semántica usan índices aproximados.

§6 · Implementación

KNN vectorizado desde cero

knn.py · verificado: predicciones idénticas a KNeighborsClassifier (k = 1, 4, 15; uniforme y por distancia), probabilidades hasta 1.5·10⁻¹⁴ y regresión hasta 2·10⁻¹³

import numpy as np

def sq_dists(A, B):
    """Distancias euclídeas al cuadrado entre filas de A (m×d) y B (n×d), sin bucles."""
    d2 = (A ** 2).sum(1)[:, None] + (B ** 2).sum(1)[None, :] - 2 * A @ B.T
    return np.maximum(d2, 0)                        # redondeo: nunca negativas

class KNN:
    def __init__(self, k=5, weights="uniform"):
        self.k, self.weights = k, weights

    def fit(self, X, y):                            # "entrenar" = guardar
        self.X, self.y = np.asarray(X, float), np.asarray(y)
        self.classes_ = np.unique(self.y)
        return self

    def _neighbors(self, Xq):
        d2 = sq_dists(np.asarray(Xq, float), self.X)
        idx = np.argpartition(d2, self.k - 1, axis=1)[:, :self.k]       # los k menores, O(n)
        order = np.take_along_axis(d2, idx, 1).argsort(1, kind="stable")
        idx = np.take_along_axis(idx, order, 1)
        dist = np.sqrt(np.take_along_axis(d2, idx, 1))
        w = np.ones_like(dist) if self.weights == "uniform" else 1 / np.maximum(dist, 1e-12)
        return idx, w

    def predict_proba(self, Xq):
        idx, w = self._neighbors(Xq)
        onehot = self.y[idx][..., None] == self.classes_            # (m, k, clases)
        votes = (w[..., None] * onehot).sum(1)
        return votes / votes.sum(1, keepdims=True)

    def predict(self, Xq):
        return self.classes_[self.predict_proba(Xq).argmax(1)]    # empate: la clase menor

    def predict_value(self, Xq):                                  # regresión: promedio (ponderado)
        idx, w = self._neighbors(Xq)
        return (w * self.y[idx]).sum(1) / w.sum(1)

Para consultas masivas, con enorme no cabe en memoria: se procesan las consultas por bloques. Y con de millones, se pasa a un índice (algorithm="kd_tree", "ball_tree") o a una biblioteca aproximada.

§7 · En producción

Con bibliotecas

vinos.py · salida real en los comentarios (scikit-learn 1.9)

from sklearn.datasets import load_wine
from sklearn.model_selection import train_test_split, GridSearchCV, cross_val_score
from sklearn.pipeline import make_pipeline
from sklearn.preprocessing import StandardScaler
from sklearn.neighbors import KNeighborsClassifier

X, y = load_wine(return_X_y=True)                     # 13 variables con escalas muy distintas
X_tr, X_te, y_tr, y_te = train_test_split(X, y, test_size=0.3, stratify=y, random_state=0)

crudo = KNeighborsClassifier(5)
print(f"sin escalar: {cross_val_score(crudo, X_tr, y_tr, cv=5).mean():.3f}")   # sin escalar: 0.734

pipe = make_pipeline(StandardScaler(), KNeighborsClassifier())
print(f"escalado:    {cross_val_score(pipe, X_tr, y_tr, cv=5).mean():.3f}")    # escalado:    0.944

grid = GridSearchCV(pipe, {"kneighborsclassifier__n_neighbors": [1, 3, 5, 7, 11, 15, 21],
                           "kneighborsclassifier__weights": ["uniform", "distance"]}, cv=5)
grid.fit(X_tr, y_tr)
print(grid.best_params_, f"prueba: {grid.score(X_te, y_te):.3f}")
# {'kneighborsclassifier__n_neighbors': 21, 'kneighborsclassifier__weights': 'uniform'} prueba: 0.981

El Pipeline no es decoración: garantiza que el escalador se ajuste solo con los pliegues de entrenamiento de cada validación. Escalar todo el conjunto antes de validar filtra información de los datos de prueba. Otras piezas útiles: KNeighborsRegressor, NearestNeighbors (solo búsqueda), KNNImputer y LocalOutlierFactor (anomalías por densidad local).

§8 · Checklist

Antes de confiar en tu KNN

  • Escala dentro de un Pipeline, ajustando el escalador solo con entrenamiento.
  • Elimina variables irrelevantes: cada una añade ruido a todas las distancias.
  • Elige (y pesos) por validación cruzada; con clases desbalanceadas, mira recall o AUC, no solo exactitud.
  • Con dos clases usa impar para evitar empates (o pesos por distancia).
  • Cuidado con duplicados y fugas temporales: un viaje casi idéntico del futuro será el vecino perfecto.
  • Mide la latencia de predicción con el tamaño real de los datos; planifica un índice si crece.
  • Si la distancia al vecino más cercano es mucho mayor de lo habitual, la predicción es una extrapolación: márcala.

Mapa del ejemplo

Para decidir si el camión nuevo está en riesgo, buscamos los 3 camiones que más se le parecen y miramos qué les pasó. Todo depende de cómo midamos "parecerse": lo haremos primero mal (con las unidades tal cual) y luego bien (escalando).

  3. Poner las dos variables de 0 a 1.
  4. Distancias escaladas y nueva votación.

  6. Dar más peso a los más cercanos.

  1. La distancia entre dos camiones

    En palabras

    Cada camión es un punto con dos coordenadas: kilómetros y temperatura. La distancia entre dos puntos es la del teorema de Pitágoras: la diferencia en cada variable, al cuadrado, sumadas, y la raíz.

    La cuenta (camión E frente al nuevo)

    E tiene 15 000 km y 99 °C; el nuevo, 14 000 km y 97 °C:

    Qué significa: los 2 grados de diferencia aportan 4 a una suma de un millón. La temperatura ya casi no cuenta, y eso que es justo lo que distingue a los camiones que se averían.

  3. Poner las dos variables de 0 a 1

    En palabras

    Para que las dos variables pesen lo mismo, convertimos cada una a una escala común: 0 para el valor más bajo de los datos y 1 para el más alto. Es el escalado mín-máx.

    La cuenta

    Kilómetros: mínimo 4 000 (A), máximo 25 000 (H). Temperatura: mínimo 87 (F), máximo 101 (C). Para el camión nuevo:

    ¿De dónde salen el mínimo y el máximo?

    De los 8 camiones que ya conocemos (los datos de entrenamiento), nunca del camión nuevo: en producción, el escalado se "aprende" una vez y se aplica igual a cada caso que llega. Otra opción habitual es la estandarización: restar la media y dividir por la desviación típica (§2).

    Qué significa: ahora "1 000 km" y "1 °C" ya no son comparables por su número, sino por lo que representan dentro de su rango: 1 000 km son el 4.8 % del rango de kilómetros y 1 °C es el 7.1 % del rango de temperaturas.

  5. ¿Por qué k = 3? Examinar a cada camión con los demás

    En palabras

    Para elegir k sin apartar datos, tapamos un camión, lo predecimos con los otros 7 y miramos si acierta. Repetimos con los 8. Se llama validación "dejando uno fuera" (leave-one-out), y con KNN es gratis: basta no contar al propio camión como vecino.

    La cuenta (variables escaladas)

    Sin escalar, el mejor resultado es 2 de 8 (con k = 1): peor que tirar una moneda.

    ¿Por qué k = 7 falla siempre?

    Al tapar un camión quedan 7, y con k = 7 votan todos. Si el tapado se averió, quedan 3 averiados y 4 sanos: gana "no", error. Si estaba sano, quedan 4 averiados y 3 sanos: gana "sí", error. Con k igual al total, KNN ya no mira la forma de los datos, solo cuenta cuántos hay de cada clase. Es el extremo "borroso" de la idea 1 de la versión sencilla.

    Qué significa: k = 1 y k = 3 empatan; elegimos 3 porque un solo vecino es más frágil ante un dato raro. Con 8 camiones esto es solo una ilustración: en serio se haría con cientos de camiones y validación cruzada.

    En palabras

    Con k = 5 entran G y D (sanos), que están bastante más lejos que E. Una variante común es que cada vecino vote con peso : los cercanos cuentan mucho, los lejanos poco.

camiones.py · reproduce los números de arriba

import numpy as np
from sklearn.neighbors import KNeighborsClassifier
from sklearn.preprocessing import MinMaxScaler
from sklearn.model_selection import cross_val_score, LeaveOneOut

X = np.array([[4000, 98], [6000, 88], [9000, 101], [12000, 90],
              [15000, 99], [18000, 87], [21000, 92], [25000, 100]], float)
averia = np.array([1, 0, 1, 0, 1, 0, 0, 1])
nuevo = np.array([[14000, 97]])

crudo = KNeighborsClassifier(3).fit(X, averia)
print(crudo.kneighbors(nuevo)[1], crudo.predict_proba(nuevo))     # [[4 3 5]] [[0.667 0.333]]

esc = MinMaxScaler().fit(X)
knn = KNeighborsClassifier(3).fit(esc.transform(X), averia)
d, i = knn.kneighbors(esc.transform(nuevo))
print(i, d.round(3), knn.predict_proba(esc.transform(nuevo)))     # [[4 2 0]] [[0.151 0.372 0.482]] [[0. 1.]]

for k in (1, 3, 5, 7):
    ok = cross_val_score(KNeighborsClassifier(k), esc.transform(X), averia, cv=LeaveOneOut())
    print(k, int(ok.sum()), "de 8")                                # 1: 8, 3: 8, 5: 6, 7: 0

Qué cambiaría en un sistema real

  • Cientos o miles de camiones y más señales: códigos de falla, presión de aceite, horas al ralentí, tipo de ruta.
  • Escalado y k elegidos por validación cruzada dentro de un Pipeline, con validación temporal.
  • Selección de variables: aquí la temperatura lo es todo; con 40 señales, las irrelevantes ensuciarían la distancia (§5).
  • Explicación gratis: junto a la alerta, el sistema puede mostrar los 3 camiones parecidos y qué les pasó, algo que un mecánico entiende al instante.
